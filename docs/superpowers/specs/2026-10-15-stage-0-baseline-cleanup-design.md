# HeritageMind 阶段 0：口径与历史债务清理设计

## 背景

`agent非遗.md` 将“统一口径并清理历史债务”定义为当前完善路线的阶段 0，并要求后续安全、数据、产品、架构、前端与部署工作按顺序推进。当前仓库仍存在可验证的口径冲突：FastAPI 应用版本为 `2.2.0`，根接口返回 `1.0.0`；OpenAPI 描述保留“23 种技艺、55,000 字、65 节点”等历史固定数字；README 的前端测试数量已经过期；Docker 与 Compose 仍把缺少入口文件的 Streamlit 构建链路描述为默认前端；旧 `/query/simple` 与 `/upload` 接口没有实际调用方。

本阶段只解决这些一致性和历史债务问题，不提前实施权限安全、API 分层、完整产品闭环或最终评测。

## 目标

1. 让应用版本、根接口、OpenAPI、README 与部署文档使用一致且可追溯的口径。
2. 删除已确认无调用、已有现行替代路径的旧接口与 Streamlit 启动链路。
3. 明确区分已实现、占位或降级、依赖外部配置、尚未上线四类状态。
4. 盘点未接线方法和活动语料临时文件，只处理能够证明安全的对象。
5. 用自动化测试和构建结果证明清理没有破坏现有主链路。

## 非目标

- 不实施阶段 1 的鉴权、上传安全、限流、CORS、密钥和健康检查改造。
- 不拆分 `api.py`，该工作属于阶段 4。
- 不增加 Agent、媒体生成、外部搜索或其他产品能力。
- 不修改题集、金标准、语料事实或评测数字。
- 不执行阶段 7 的正式检索、回答质量、多 Agent 消融或性能评测。

## 方案选择

采用“完整阶段 0 清理”方案：既修正文档口径，也删除能够确认失效的代码和部署入口。未采用只改文档的最小方案，因为它会继续保留不可构建的 Streamlit 路径和重复 API；未采用提前拆分后端入口的方案，因为它会越过路线图进入阶段 4，并显著扩大本轮回归范围。

## 设计

### 1. 应用版本与 OpenAPI

- 建立单一应用版本来源，FastAPI `version` 与根接口响应均从该来源读取。
- 根接口保留轻量服务发现信息，但不返回独立维护的版本字符串。
- OpenAPI 描述删除历史固定数量，不把名录覆盖、深度资料、活动图书片段或图谱节点混成单一“知识库规模”。
- OpenAPI 引导调用方从 `/dashboard/summary`、`/documents/summary` 与 `/graph/stats` 获取当前运行实例的统计值。
- 本阶段不在应用导入或 OpenAPI 生成阶段访问数据库或加载完整语料，避免文档生成依赖外部服务。

### 2. 旧接口与未接线代码

- 删除 `/query/simple`。Vue 主链路使用 `/query/stream`，非流式调用使用 `/query`；前端未使用的 `sendQuerySimple()` 同步删除。
- 删除旧 `/upload`。知识文档上传的现行入口为 `/documents/upload`；旧接口专用的响应模型在无其他调用后删除。
- 对 `dispatcher.fuse_with_debate` 及其他疑似未接线辅助方法做静态调用盘点。只有同时满足“仓库内零调用、存在现行替代路径、测试不依赖”的方法才删除。
- 对无法证明安全删除的扩展点生成盘点记录并保留，不以猜测代替调用证据。
- 删除路由后不增加兼容别名或弃用期；这是经用户确认的清理策略。

### 3. Vue 唯一前端

- 删除根 Dockerfile 中已失效的 Streamlit 构建阶段及相关注释。
- 删除 `config.py` 中不再使用的 Streamlit 端口配置。
- Compose 的默认前端改为 Vue 开发服务，使 `docker compose up` 启动 MySQL、API 与 Vue；Vue/Nginx 生产服务继续由 production profile 管理。
- README、部署说明和示例命令只推荐 Vue，不再保留 Streamlit 的默认端口、健康检查或启动说明。
- 不在本阶段重构前端 Dockerfile或生产 Nginx 细节，除非当前配置因服务改名需要同步引用。

### 4. 状态与数字口径

- README 增加状态矩阵，分别标记：已实现；占位或明确降级；需要联网、模型或第三方配置；尚未上线。
- 百度/Web 外部搜索等未真正接线的能力不得使用完成式表述。
- README 中的测试数、复测日期、基线提交和已知限制以本阶段实际执行结果为准，不从路线图复制旧数字。
- 文档说明“官方名录覆盖、深度资料覆盖、图片覆盖、活动图书片段、图谱规模、检索指标”是不同统计口径。
- 历史设计文档保留原始版本事实，不批量改写；当前 README、Swagger、部署说明和有效路线图使用现行口径。

### 5. 活动语料残留检查

- 检查活动语料目录中名称异常的临时文件、未完成写入文件和构建残留。
- 删除前必须证明文件未被 `catalog.json`、活动清单或其他版本化索引引用，并且能够识别其来源和用途。
- 不删除受 Git 忽略保护的合法本地图书正文，不根据文件名猜测内容是否无用。
- 若没有可安全删除的残留，只记录检查结果，不制造无意义改动。

## 数据流与兼容性

应用启动时从单一版本来源创建 FastAPI 实例。根接口直接复用该版本；OpenAPI 只描述能力和动态统计入口，不自行读取运行数据。浏览器端问答继续通过 `/query/stream`，其他消费者可使用 `/query`。文档上传只保留 `/documents/upload`。默认 Compose 数据流变为浏览器 → Vue 开发服务 → API → MySQL/活动语料；生产 profile 保持浏览器 → Nginx/Vue 静态资源 → API。

本阶段有两项明确的破坏性兼容变化：`/query/simple` 和 `/upload` 被移除，Streamlit 镜像目标与默认服务被移除。仓库内没有这些旧入口的有效消费者，且用户已确认无需兼容期。

## 错误处理

- 删除旧接口后应返回 FastAPI 标准 404，不增加伪兼容响应。
- 动态统计端点保持各自既有错误语义；OpenAPI 描述不因统计依赖不可用而失效。
- Compose 配置必须能被 `docker compose config` 解析；若本机缺少 Docker，则记录未执行原因，不把跳过写成通过。
- 清理过程中发现的阶段 1 安全问题只记录到已知限制，不在本阶段顺手改变其行为。

## 测试策略

所有行为修改遵循测试先行：

1. 新增测试，断言 FastAPI 元数据版本与根接口版本一致。
2. 新增测试，断言 OpenAPI 描述不含 `23 种`、`55,000`、`65 节点` 等旧固定口径，并指向动态统计端点。
3. 新增测试，断言 `/query/simple` 与 `/upload` 不再出现在 OpenAPI 路由中。
4. 新增文本契约测试，断言 Docker、Compose、配置和 README 不再把 Streamlit 作为可用前端，且默认 Compose 包含 Vue 前端。
5. 每个测试先运行并确认因旧行为而失败，再做最小实现使其通过。
6. 运行受影响测试后，执行后端全量离线测试、前端 Vitest、TypeScript 检查和生产构建。
7. 将真实测试数量、日期、基线提交、跳过项和构建警告写入 README；不运行正式数据评测。

## 验收标准

- FastAPI 应用版本与根接口版本完全一致，仓库只有一个现行版本来源。
- 当前 OpenAPI、README 和部署文档不存在旧固定规模或 Streamlit 默认前端表述。
- `/query/simple`、旧 `/upload` 和其无调用前端封装均已移除。
- `docker compose up` 的默认前端是 Vue，配置能够通过静态解析。
- 未接线代码和活动语料残留均有基于调用或清单引用的处置结论。
- 后端离线测试、前端测试、类型检查和生产构建均有真实结果；任何失败、跳过或警告明确记录。
- Git 工作区不包含与阶段 0 无关的修改。
