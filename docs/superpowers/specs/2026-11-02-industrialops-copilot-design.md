# IndustrialOps Copilot 设计规格

日期：2026-11-02  
状态：已确认设计，尚未进入实施  
来源项目：HeritageMind（仅复用工程能力，不直接改写其非遗产品定位）

## 1. 背景与目标

HeritageMind 已具备 FastAPI、Vue 3、LangGraph、多路检索、重排、引用、知识缺口检测、知识图谱、会话、数据治理、Docker 部署和评测基础。工业桥接项目不应只是把非遗文档替换成设备手册，而应把这些能力抽象为可配置的工业设备运维平台。

新项目暂定名为 **IndustrialOps Copilot**，定位为：

> 面向多类工业设备的可配置运维知识、故障诊断与维修工单辅助平台。

项目采用“一深一浅”案例组合：

- CNC 数控机床：深度主案例，体现通用制造业覆盖能力；
- 工业干式真空泵：轻量迁移案例，验证架构可迁移性并建立半导体相关性。

项目证明的不是“一套知识可以诊断所有设备”，而是：不同设备通过独立设备包接入后，可以复用同一套知识治理、检索、诊断、安全约束和工单流程。

## 2. 范围与非目标

### 2.1 本期范围

1. 建立与具体设备解耦的工业资产、部件、报警、症状、故障原因、检查步骤、安全约束和工单数据模型。
2. 建立设备包契约，支持 CNC 和干式真空泵使用独立资料、规则和评测集。
3. 完成 CNC 数控铣床设备包的完整问答、故障排查、安全校验和模拟工单闭环。
4. 完成一个干式真空泵轻量设备包，验证核心代码无需按设备重写。
5. 保留来源级引用、型号与文档版本约束、知识缺口检测和可复现评测。
6. 使用模拟设备台账、报警历史和维修工单接口，展示与 CMMS/EAM/MES 类系统集成的方式。

### 2.2 非目标

1. 不声称能够替代持证维修工程师、设备厂商或企业安全规程。
2. 不直接控制机床、真空泵或其他真实设备。
3. 不在第一阶段实现预测性维护模型、剩余寿命预测或实时传感器流处理。
4. 不把 AI4I 等公开合成数据伪装成具体品牌机床的真实运行数据。
5. 不覆盖所有 CNC 控制器、所有机床型号或所有真空泵类型。
6. 不将受版权保护的完整厂商手册提交到公开 Git 仓库。
7. 不直接把 HeritageMind 改造成工业项目，避免破坏其现有定位、数据和评测历史。

## 3. 总体架构

```text
用户问题
  ↓
设备上下文解析
  ├─ 设备包
  ├─ 厂商/型号
  └─ 文档版本
  ↓
限定范围的混合检索
  ├─ 官方手册
  ├─ 报警码
  ├─ 安全规范
  ├─ 模拟维修工单
  └─ 设备知识图谱
  ↓
故障诊断编排
  ├─ 症状与报警归一化
  ├─ 候选原因排序
  ├─ 检查步骤生成
  └─ 证据完整性检查
  ↓
安全规则与知识缺口门控
  ├─ 高风险动作拦截
  ├─ 型号不明时拒绝确定性结论
  └─ 证据不足时明确升级人工
  ↓
结构化回答
  ├─ 当前判断
  ├─ 排查顺序
  ├─ 安全前置条件
  ├─ 来源引用
  └─ 不确定性说明
  ↓
可选：生成模拟维修工单草稿
```

核心原则：安全门控不依赖模型自行发挥。能够结构化表达的停机、断电、泄压、挂牌上锁、资质和禁止操作要求，优先由确定性规则执行；LLM 只负责在规则允许的范围内组织和解释证据。

## 4. 通用领域模型

### 4.1 核心实体

| 实体 | 说明 |
|---|---|
| EquipmentPack | 一类设备的资料、规则、图谱和评测集合 |
| Equipment | 具体设备资产或演示设备 |
| Manufacturer | 厂商 |
| Model | 型号及版本范围 |
| Component | 主轴、刀库、泵体、密封等部件 |
| Symptom | 异响、过热、无法启动等现象 |
| Alarm | 报警码、报警文本及适用范围 |
| PossibleCause | 候选故障原因 |
| InspectionStep | 检查步骤及顺序 |
| MaintenanceAction | 维修或保养措施 |
| SafetyConstraint | 风险、前置条件、人员资质和禁止事项 |
| WorkOrder | 维修工单及处置闭环 |
| Evidence | 可定位到来源、版本、章节和页码的证据 |

### 4.2 通用关系

```text
Equipment HAS_COMPONENT Component
Alarm APPLIES_TO Model
Symptom MAY_INDICATE PossibleCause
Alarm MAY_INDICATE PossibleCause
PossibleCause VERIFIED_BY InspectionStep
PossibleCause RESOLVED_BY MaintenanceAction
InspectionStep REQUIRES SafetyConstraint
MaintenanceAction REQUIRES SafetyConstraint
WorkOrder INVOLVES Equipment
WorkOrder CONFIRMS PossibleCause
Evidence SUPPORTS Alarm/PossibleCause/InspectionStep/MaintenanceAction
```

设备知识不能跨型号自动继承。只有设备包显式声明兼容范围时，同一条报警或维修措施才可用于多个型号。

## 5. 设备包契约

每个设备包使用相同目录契约：

```text
equipment_packs/<pack_id>/
├── pack.yaml
├── source_manifest.json
├── alarm_codes.json
├── maintenance_rules.json
├── safety_rules.json
├── graph_relations.jsonl
├── synthetic_assets.json
├── synthetic_work_orders.jsonl
└── evaluation/
    ├── retrieval_cases.jsonl
    ├── answer_cases.jsonl
    └── safety_cases.jsonl
```

`pack.yaml` 至少声明：

- `pack_id`、设备类别和显示名称；
- 支持的厂商、型号和版本范围；
- 允许使用的文档集合；
- 设备特有的同义词和报警格式；
- 工单字段映射；
- 高风险动作和升级人工规则；
- 设备包版本和内容哈希。

加载失败、字段缺失、版本不兼容或来源未发布时，设备包保持不可用状态，不静默进入检索。

## 6. CNC 数控机床深度案例

### 6.1 案例边界

第一版只选择一种数控铣床及对应控制/服务资料，不把不同厂商报警码混在同一知识空间。建议覆盖：

- 主轴系统；
- 刀库与换刀机构；
- X/Y/Z 伺服轴；
- 润滑系统；
- 冷却液系统；
- 操作与维修安全要求。

### 6.2 主要能力

1. 根据报警码检索含义、适用型号、候选原因和官方处理依据。
2. 根据自然语言症状识别相关部件和可能原因。
3. 结合报警、症状和模拟设备状态，生成由低风险、低成本到高风险的排查顺序。
4. 对拆卸、防护门旁路、电气检查、机械复位等动作执行安全门控。
5. 查询模拟报警历史、设备台账和维修工单。
6. 生成待人工确认的工单草稿，绝不自动下发维修动作。

### 6.3 典型场景

```text
换刀过程中刀库停在两个刀位之间并出现定位报警
→ 确认设备型号和控制系统
→ 检索报警及刀库服务资料
→ 关联位置传感器、机械障碍、驱动和气路候选原因
→ 给出停机和能量隔离前置条件
→ 输出检查顺序、证据和升级人工条件
→ 生成模拟维修工单草稿
```

## 7. 工业干式真空泵轻量迁移案例

### 7.1 案例边界

选择一个公开资料充分的干式真空泵型号族，只覆盖有限的运维和故障排查问题：

- 无法启动或运行中停止；
- 达不到目标真空度；
- 抽气时间明显延长；
- 系统或管路泄漏；
- 温度过高或冷却不足；
- 过滤、密封和管路异常；
- 异常振动或噪声；
- 停机、隔离和维修安全要求。

### 7.2 迁移验收

真空泵设备包主要验证：

1. 不修改通用工作流即可加载新设备包；
2. CNC 报警、工单和证据不会污染真空泵检索结果；
3. 真空泵特有的压力、泄漏、冷却和密封关系可通过通用领域模型表达；
4. 对型号不明、过程介质不明和高风险拆修问题能够保守拒答或升级人工；
5. 检索、回答和安全评测可以独立运行并生成设备包级报告。

## 8. 数据来源与治理

### 8.1 数据层级

1. **厂商官方资料**：操作手册、服务手册、报警资料、维护指南和安全手册，是设备事实的首要来源。
2. **政府及权威安全资料**：补充能量隔离、挂牌上锁、人员资质和检维修管理要求。
3. **模拟企业数据**：设备台账、报警历史和维修工单，由项目生成并显式标记 `synthetic`。
4. **公开数据集**：只在来源、许可和设备边界清楚时使用；第一阶段不接入预测模型。

### 8.2 来源清单字段

每份资料至少记录：

- 来源机构、标题和原始 URL；
- 厂商、设备类别、型号和版本；
- 文档类型、发布日期、章节和页码；
- 获取日期、文件哈希和解析状态；
- 版权/许可状态和是否允许公开再分发；
- 审核状态：`draft`、`published` 或 `deprecated`。

厂商原始手册默认保存在 Git 忽略目录。公开仓库只提交来源清单、下载说明、哈希、解析代码、明确允许分发的数据，以及自行编写并标明模拟的数据。

### 8.3 数据诚信要求

- AI4I 等合成数据不得被描述为某品牌 CNC 的真实运行数据。
- 模拟工单必须带 `SIM-` 编号或 `source_type: synthetic`。
- 不通过删题、改预期证据或混用不同语料版本提升指标。
- 检索指标、回答质量、安全合规和预测模型指标必须分开报告。

## 9. Agent 与工作流职责

第一阶段保留有限角色，避免为了展示多 Agent 而增加无意义调用：

| 组件 | 职责 |
|---|---|
| EquipmentContextResolver | 确认设备包、厂商、型号和问题类型；歧义时要求补充信息 |
| EvidenceRetriever | 在设备范围内执行混合检索、重排和图谱查询 |
| FaultDiagnosisAgent | 基于证据组织症状、原因和检查步骤，不越过证据生成确定性结论 |
| SafetyPolicyGate | 执行确定性安全规则，拦截高风险或缺少前置条件的建议 |
| GapDetector | 识别证据不足、型号不匹配和超出知识边界的问题 |
| WorkOrderDraftService | 把已确认信息转成模拟工单草稿，不自动创建真实工单 |

动态辩论不是 MVP 的必要条件。只有当多个候选原因都有有效证据、且协作能改善可解释性时才启用；安全规则不能被辩论结果覆盖。

## 10. 回答结构与错误处理

标准回答结构：

1. 设备与型号适用范围；
2. 当前问题摘要；
3. 已有证据支持的候选原因；
4. 建议排查顺序；
5. 安全前置条件和禁止操作；
6. 来源引用；
7. 不确定性、缺失信息和升级人工条件；
8. 可选工单草稿。

关键失败处理：

- 未识别设备包：不进入诊断，要求用户选择设备类型；
- 型号不明且报警含义依赖型号：只返回补充信息请求；
- 检索无有效证据：触发知识缺口，不生成维修步骤；
- 安全规则冲突：以更保守的规则为准；
- 外部模拟工具失败：保留本地证据回答，明确标记工具不可用；
- LLM 失败：返回可读的证据列表和失败状态，不把检索片段伪装成完整诊断。

## 11. 前端信息架构

第一阶段沿用现有 Vue 3 技术栈，页面重点改为：

1. 设备包、厂商、型号和模拟设备选择；
2. 问题输入及当前设备上下文；
3. 结构化诊断卡片；
4. 高风险安全提示区；
5. 引用证据侧栏，展示来源、版本、章节和页码；
6. 设备关系图；
7. 模拟维修工单草稿；
8. 管理端设备包状态、来源审核和评测报告。

前端不得使用“自动维修”“保证修复”等误导性文案，应统一使用“辅助诊断”“建议检查”“需人工确认”。

## 12. 评测与测试

### 12.1 设备包级评测

CNC 深度案例覆盖：

- 报警码直问；
- 自然语言故障现象；
- 相似故障混淆；
- 多证据排查；
- 安全风险问题；
- 型号不匹配；
- 知识库外问题。

真空泵轻量案例覆盖：

- 启动失败；
- 真空度不足；
- 泄漏和管路问题；
- 冷却与过热；
- 型号未知；
- 高风险维修请求；
- 知识库外问题。

### 12.2 平台级验收

1. 设备包隔离：CNC 问题不能引用真空泵资料，反之亦然。
2. 版本隔离：不同型号或版本报警不能未经声明混用。
3. 安全门控：危险操作在缺少停机、断电、泄压或资质条件时必须被拦截。
4. 引用完整性：诊断中的关键事实必须能定位到有效证据。
5. 知识缺口：无证据问题必须拒绝确定性诊断。
6. 工单诚信：所有演示工单都明确标记为模拟数据。
7. 可迁移性：新增真空泵设备包不需要改写 CNC 专属逻辑之外的核心流程。

检索召回、重排效果、回答事实质量、安全合规率和端到端延迟分别报告，不用单一指标替代整体质量。

## 13. 与 HeritageMind 的复用边界

### 13.1 可复用

- FastAPI、Vue 3、认证、会话和部署基础；
- 文档导入、审核和发布状态；
- BM25、向量、RRF 和重排组件；
- 引用、知识缺口和评测框架；
- LangGraph 编排模式；
- 知识图谱展示和维护任务机制。

### 13.2 必须泛化或替换

- `craft_name`、`craft_id` 等非遗专属标识；
- craft/history/heritage 专家角色及提示词；
- 非遗分类、百科、传承人和媒体语义；
- 非遗知识图谱关系；
- 非遗评测集和页面文案；
- 任何依赖技艺名加权的检索规则。

IndustrialOps Copilot 应作为独立派生项目维护。HeritageMind 保留其仓库、README、数据、历史指标和个人品牌定位。

## 14. 成功标准

达到以下条件时，项目可以作为求职工业桥接案例：

1. CNC 主案例具备完整的设备上下文、故障检索、安全门控、引用和工单草稿闭环。
2. 真空泵设备包在不重写核心工作流的前提下成功接入。
3. 两个设备包的数据、索引、报警和评测相互隔离。
4. 所有公开或模拟数据均有明确来源、版本、许可或模拟标识。
5. 评测能复现，并保留失败样本和适用边界。
6. README 清楚区分辅助诊断、模拟数据和真实设备控制。
7. 面试时能够演示同一平台如何服务通用制造与半导体相关设备场景，而不夸大为全工业通用诊断系统。

## 15. 后续阶段

设计批准后的下一步是编写实施计划。实施计划应按以下顺序拆分，但本设计阶段不执行代码变更：

1. 从 HeritageMind 提取可复用的通用能力和领域耦合清单；
2. 建立独立项目和设备包契约；
3. 完成 CNC 资料治理、数据模型和深度案例；
4. 完成安全门控与模拟工单接口；
5. 建立 CNC 评测基线；
6. 接入真空泵设备包并完成跨设备隔离验收；
7. 最后再评估是否增加 AI4I 预测性维护工具。
