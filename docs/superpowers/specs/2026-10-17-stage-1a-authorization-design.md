# HeritageMind 阶段 1A：权限矩阵与资源归属设计

## 背景

HeritageMind 阶段 0 已统一版本、接口和部署口径。路线图下一步是阶段 1“权限、安全与资源边界收口”。该阶段同时包含鉴权、上传安全、限流、密钥、异常、健康检查和依赖降级，不能在一个低风险变更中完成，因此拆为四个连续子阶段：

1. 1A：权限矩阵与资源归属；
2. 1B：上传、路径和文件资源边界；
3. 1C：CORS、认证、密钥、限流与异常响应；
4. 1D：Liveness、Readiness 与依赖降级。

当前代码已经有 `get_current_user`、`get_optional_user` 和 `require_admin`，但 Prompt、媒体写操作、知识文档上传、索引重建和手动转写没有统一绑定管理员依赖；公开媒体查询也没有强制过滤 `published`。会话、历史和反馈已经按用户过滤，但收藏创建时接受任意 `chat_id`，没有验证聊天归属。

## 目标

1. 让所有管理写操作在后端强制要求管理员身份。
2. 将公开媒体读模型与管理员媒体读模型分离，草稿和审核中内容不得公开。
3. 确保媒体搜索、详情、文件和音频结果遵循同一发布状态。
4. 补齐收藏关联聊天记录时的资源归属验证。
5. 让前端操作入口与后端权限一致，同时明确前端角色判断不是安全边界。
6. 建立可自动检查的敏感路由权限契约，防止后续回归。

## 非目标

- 不处理文件扩展名、MIME、魔数、大小、页数、时长、分块写入和路径规范化；这些属于 1B。
- 不修改 CORS、密码策略、生产密钥校验、API Key 存储、限流或统一异常响应；这些属于 1C。
- 不拆分 liveness/readiness，不实现超时、重试或熔断；这些属于 1D。
- 不拆分 `api.py` 路由与 Service 架构；完整拆分属于阶段 4。
- 不新增 Prompt 版本发布、媒体审核工作台或后台大规模重构；完整产品闭环属于阶段 3。
- 不改变匿名问答策略；该策略在 1C 通过部署配置设计。

## 方案选择

采用“权限矩阵 + 公开/管理读模型分离”。不采用只给写接口补 `require_admin` 的最小方案，因为它无法阻止草稿通过公开列表、详情、文件或搜索泄露；不采用提前拆分全部路由的方案，因为它会越过阶段 1 进入阶段 4并扩大回归范围。

## 权限矩阵

| 能力 | 匿名用户 | 登录用户 | 管理员 |
| --- | --- | --- | --- |
| 读取已发布媒体列表、详情和文件 | 允许 | 允许 | 允许 |
| 搜索已发布图片、相似图片和音频 | 允许，资源限制留到 1B/1C | 允许 | 允许 |
| 查看全部媒体及审核状态 | 禁止 | 禁止 | 允许 |
| 上传、删除、修改媒体状态 | 禁止 | 禁止 | 允许 |
| 查看转写内部状态、手动重试转写 | 禁止 | 禁止 | 允许 |
| 重建 Embedding、图片索引、音频索引 | 禁止 | 禁止 | 允许 |
| 上传知识文档 | 禁止 | 禁止 | 允许 |
| Prompt 增删改查 | 禁止 | 禁止 | 允许 |
| 会话、历史、反馈、收藏 | 禁止 | 仅自己的资源 | 仅自己的资源，除非使用专用管理接口 |
| 既有 `/admin/*` 接口 | 禁止 | 禁止 | 允许 |

Prompt 当前没有公开前端消费者，且响应包含 `system_prompt`。经用户确认，`/prompts` 与 `/prompts/{id}` 的读取和写入全部改为管理员专用，不保留公开读取字段。

## 后端设计

### 1. 敏感路由统一鉴权

下列接口显式注入 `Depends(require_admin)`：

- Prompt：列表、详情、创建、更新、删除；
- 媒体：上传、删除、状态修改、手动转写；
- 索引：Embedding、图片、音频重建；
- 知识文档：`/documents/upload`；
- 管理媒体列表：新增 `/admin/media`。

现有 `/admin/*` 路由继续使用 `require_admin`。匿名调用敏感接口返回 401；有效普通用户调用返回 403。不能只依赖 `localStorage` 中的角色。

### 2. 媒体公开投影

媒体 Service 增加显式的公开查询：

- `list_published_media(...)`：在数据库查询层固定 `status == "published"`，过滤条件和总数使用相同谓词；
- `get_published_media(media_id)`：只返回已发布记录；
- `get_published_media_by_storage_name(media_type, filename)`：先在数据库中确认记录存在且已发布，再返回文件路径所需元数据。

公开 `/media/list` 和 `/media/{id}` 只使用公开查询。`/media/file/{media_type}/{filename}` 不再只凭路径片段直接返回文件，而是先验证对应数据库记录已发布。不存在、未发布或无权读取统一返回 404。

新增 `/admin/media` 使用全量查询，允许管理员查看 `draft/reviewed/published`。未发布记录的公开 URL 不应作为可访问资源返回；阶段 1A 不新增带 Token 的媒体预览机制。

### 3. 搜索与转写状态

- 图片文字搜索、相似图片搜索和音频文字搜索在返回前按数据库中的 `published` 媒体集合过滤。
- 图片和音频索引可以包含待审核记录以支持管理员流程，但公开搜索不得仅信任向量索引中的状态副本，必须回查当前数据库状态。
- `/media/{id}/transcript` 改为管理员接口，因为响应包含失败原因、重试次数和内部处理状态。
- `/media/{id}/transcribe` 继续保持现有状态机，但增加管理员依赖。

### 4. 用户资源归属

- 收藏创建携带 `chat_id` 时，先查询 `ChatHistory.id == chat_id AND user_id == current_user.id`；不属于当前用户时返回 404，不创建收藏。
- 收藏列表和删除继续按当前用户过滤。
- 会话详情、会话消息、聊天详情和反馈沿用现有用户过滤，并增加回归测试证明跨用户访问失败。
- 越权资源统一使用 404，避免向调用者泄露目标资源是否存在。

## 前端设计

- 媒体页始终允许浏览公开已发布内容。
- 管理员登录后，媒体页调用 `/admin/media` 获取全量记录，并显示上传、删除和状态修改操作；非管理员不渲染这些操作。
- 前端从认证 Store 的当前用户读取角色。`localStorage` 只用于恢复界面状态，任何伪造都无法绕过后端 `require_admin`。
- 修复当前媒体筛选参数错误：`listMedia` 的第一个参数使用 `selectedCraft`，第二个参数使用 `filterType`。
- 前端对 401、403 和 404 显示明确提示；全局登录恢复与统一错误处理留到阶段 1C/3。
- 本阶段不把完整媒体审核工作台塞入现有页面，只提供状态切换所需的最小管理操作。

## 响应与错误语义

- 未携带有效 Token 的管理请求：401，保留 `WWW-Authenticate: Bearer`。
- 已登录普通用户请求管理能力：403，响应“需要管理员权限”。
- 公开读取不存在或未发布媒体、跨用户读取资源：404。
- 非法媒体状态仍由请求模型或 Service 返回 422；允许的状态固定为 `draft/reviewed/published`。
- 后端日志可以记录路由、操作者 ID 和对象 ID，但不记录 Token、API Key、Prompt 内容或私密媒体内容。

## 测试策略

所有行为修改遵循测试先行，并逐项确认 RED 的失败原因正确：

1. 路由契约测试枚举敏感端点，断言其依赖树包含 `require_admin`。
2. Prompt 测试覆盖匿名 401、普通用户 403、管理员读取和写入成功。
3. 媒体 Service 测试覆盖公开列表总数与结果同时过滤 `published`。
4. 媒体 API 测试覆盖草稿列表不可见、草稿详情/文件 404、已发布可读、管理员可见全量记录。
5. 搜索测试覆盖向量结果命中草稿时仍被数据库状态过滤。
6. 管理操作测试覆盖媒体上传、删除、状态修改、转写与三类索引重建的 401/403。
7. 归属测试覆盖他人聊天详情、会话消息、反馈和收藏关联均失败；自己的资源不回归。
8. 前端测试覆盖普通用户不显示管理操作、管理员显示操作、媒体筛选参数正确。
9. 完成后运行后端全量离线测试、前端 Vitest、TypeScript 检查和生产构建。

## 兼容性与迁移

- Prompt 公开读取被移除，是经用户确认的有意安全收紧；仓库内没有公开消费者。
- `/media/list` 的响应结构保持不变，但数据范围收紧为已发布记录。
- 新增 `/admin/media`，现有管理员前端改用该端点。
- 未发布媒体的旧公开 URL 将返回 404；数据库和磁盘文件不删除。
- 不需要数据库结构迁移；只使用现有媒体 `status` 字段。

## 验收标准

- 权限矩阵中的所有管理能力在后端均要求管理员，匿名和普通用户无法写入或触发重建任务。
- Prompt 内容不能通过匿名或普通用户接口读取。
- 草稿和审核中媒体不能通过列表、详情、文件、图片搜索或音频搜索公开获得。
- 管理员能够查看全部媒体并执行本阶段保留的管理动作。
- 收藏无法关联其他用户的聊天记录，会话、历史和反馈归属测试通过。
- 前端角色伪造不能绕过后端权限；普通用户界面不展示无权操作。
- 后端全量测试、前端测试、类型检查和生产构建有真实记录。
- 文档明确标记阶段 1B、1C、1D 尚未完成，不把 1A 宣称为阶段 1 全部完成。
