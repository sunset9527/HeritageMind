# HeritageMind v1.8 实施计划：动态 Agent 协作与实时 DAG

> 前置规格：[v1.8 动态 Agent 协作与实时工作流可视化设计](2026-09-11-v1.8-dynamic-agent-collaboration-design.md)

## 实施原则

- 每个行为先以离线、确定性 pytest 表达，并确认该测试因 v1.8 功能缺失而失败；只随后写使之通过的最小生产实现。
- 不改写 v1.4 音频、v1.5 会话记忆、v1.6 图谱检索或数据库模式；本期不新增迁移。
- `/query` 既有响应字段及 `/query/stream` 既有 `step/msg` 事件保持兼容。
- 事件和前端状态只使用脱敏的用户可读摘要，绝不传送 prompt、API Key、完整会话上下文或完整检索文本。

## 1. Agent 注册表与 Router 白名单

**文件**：新增 `src/agents/registry.py`；更新 `src/agents/dispatcher.py`、`src/agents/__init__.py`；新增 `tests/test_v18_agent_registry.py`。

1. 先写测试：注册表能按 Router 给出的顺序返回去重后的已注册 Agent；未知 ID 被过滤；空集合和单 Agent 均安全处理；新增注册 Agent 不需要修改协作引擎。
2. 定义 `AgentDefinition`（ID、显示名、图标、能力、工厂）和只读 `AgentRegistry`，默认注册当前三位专家。
3. 将 Dispatcher 的 Router 工具 schema 改为由注册表生成允许 ID；保留既有模块常量或等价默认 schema，避免已有 Router 测试/API 使用者中断。
4. Router 解析和关键词降级后的专家列表统一经过注册表清洗；未知模型输出不实例化、不进入响应、不发送事件。

**验收**：新增注册表测试及现有 Dispatcher/Router 测试全通过。

## 2. 运行时事件模型与线程安全事件队列

**文件**：新增 `src/workflow/events.py`；更新 `src/workflow/state.py`、`src/workflow/graph.py`、`src/workflow/nodes.py`；新增 `tests/test_v18_workflow_events.py`。

1. 先写测试：合法事件保留 `event/step/msg/run_id`，非法状态被拒绝；payload 递归过滤敏感字段；事件从同步节点进入异步队列时顺序稳定。
2. 定义受白名单约束的运行事件：`workflow_started`、节点 started/completed/skipped/fallback、`workflow_graph_updated`、`agent_message`、`done`、`error`；集中构造 SSE 安全 payload。
3. `WorkflowEventEmitter` 接受可选 sink；无 sink 时为无操作，确保普通 `/query` 不受影响；同步 LangGraph 节点通过线程安全的队列桥接给 `/query/stream`。
4. 为图的可执行节点加轻量包装：开始时发 `node_started`，正常结束发 `node_completed`，异常由既有节点的安全降级路径标为 `node_fallback`。条件节点在判断时显式发 `node_skipped`。
5. 在初始状态中携带仅运行期使用的 emitter 和 `run_id`，并确保 `state_to_response`、聊天历史和日志不序列化运行期对象。

**验收**：节点开始/结束事件可在节点内部即时发出，普通 `query()` 与既有 v1.6 response contract 不回归。

## 3. 动态协作引擎

**文件**：更新 `src/agents/debate_engine.py`，必要时新增 `src/agents/collaboration.py`；更新 `config.py`、`src/workflow/nodes.py`；新增 `tests/test_v18_collaboration.py`。

1. 先写测试：少于两位参与者时协作被跳过；三个、两个和新增注册 Agent 的协作轮次不依赖固定专家顺序；所有消息的 kind 受白名单约束；达到 `collaboration_max_messages` 后停止；某参与者失败会发 fallback 且其余参与者继续。
2. 提供通用协作计划器，输入为本次注册 Agent、首轮回答和共享检索上下文；只产生有限的 `supplement/challenge/response/agree` 行动，不再次调用 Retriever。
3. 用 AgentDefinition 的工厂/元数据替代 `DebateEngine` 内部固定三专家信息与固定轮次。保留既有 `DebateSession` 输出适配层，以免当前 `DebateTimeline` 和历史消息失效。
4. 每次协作动作产生一条短、可展示的 `agent_message`，并将新的/修订的回答作为融合输入；实际融合仍调用既有 Dispatcher 融合路径。
5. 复用现有 `debate_enabled` 语义，并增加默认保守的 `collaboration_max_messages` 配置；LLM、解析或 Agent 调用异常均降级到不协作的既有融合。

**验收**：动态参与者、轮次上限和失败降级均由无网络 mock 测试覆盖；没有实现中对 `craft/history/heritage` 的固定协作顺序。

## 4. 实时 SSE Producer 与 API 契约

**文件**：更新 `api.py`、`src/workflow/state.py`；新增 `tests/test_v18_stream_contract.py`。

1. 先写 async API 测试：流的首个结构化事件是 `workflow_started`；随后节点、动态图与协作消息按产生顺序到达；终态 `done` 含旧字段、最终轨迹和协作摘要；旧客户端仍能读取每个事件的 `step/msg`。
2. 改造 `/query/stream`：为一次请求建立 `run_id` 和 asyncio queue，在后台运行 LangGraph，同时消费事件队列并立即 yield SSE；不要等待整张图结束才推送事件。
3. 由节点完成 chunk 补充旧的步骤文案；由 emitter 发送真正的 started/fallback/协作事件，避免把完整内部 state 写入 SSE。
4. `workflow_started` 发送基础 DAG。Router/分派完成后发 `workflow_graph_updated`，只包含已验证的实际 Agent 节点与边。
5. 保留会话保存、偏好学习、API 覆盖 `finally` 清理和错误事件行为；客户端中断时取消 producer task，关闭 queue，不持久化虚假完成状态。

**验收**：SSE 的实时顺序、动态图更新、断开清理与敏感字段隔离全部自动化测试；`/query` 响应兼容测试保持通过。

## 5. Vue 实时 DAG 与协作时间线

**文件**：新增 `frontend/src/components/chat/RealtimeWorkflowDag.vue`，必要时新增事件归约工具；更新 `frontend/src/api/query.ts`、`frontend/src/stores/chat.ts`、`frontend/src/types/index.ts`、`frontend/src/views/ChatView.vue`。

1. 先为纯 TypeScript 事件归约函数写测试或最小可执行断言：节点状态转移、动态节点/边去重、协作消息排序、未知事件忽略。
2. 扩展 SSE 解析器，将 `event` 事件保留给 store；旧 `step` 处理继续可用。每次事件只更新当前正在生成的 assistant message。
3. 定义严格的运行时类型：DAG 节点、边、状态、协作消息和 SSE payload；历史消息字段全部可选，避免旧聊天记录渲染失败。
4. 用现有 Vue/Tailwind/CSS/SVG 实现实时 DAG：节点显示 pending/running/completed/skipped/fallback；Router 返回后动态插入 Agent 节点和连接；协作边使用虚线；移动端保持纵向可读。
5. 图下显示实时协作时间线。流式中默认展开，完成后可收起；没有 v1.8 事件的消息继续渲染 v1.6 `WorkflowTrace`。
6. 不添加图编辑器、WebSocket 或后台管理依赖。

**验收**：使用模拟 SSE 事件能看到状态逐步转换；`npx vue-tsc --noEmit` 与 `npm run build` 通过，既有辩论面板不受影响。

1. 先运行新增测试，再运行 `python -m pytest tests/ --basetemp <可写临时目录>`，记录真实的通过/跳过数。
