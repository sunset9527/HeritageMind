# 本地非遗图书语料切换设计

## 背景与目标

`<local books directory>` 中保存 10 本本地非遗参考书（9 个 PDF、1 个 EPUB，约 2.73 GiB）。项目现有默认语料是 `data/knowledge_sources/manifest.json` 中的 591 条已审核网页/Markdown 来源。

本次目标是让这批本地图书成为 HeritageMind 唯一的默认检索语料，同时保留现有资料文件和数据库记录，不做删除或覆盖。图书原件和从中提取的大段版权文本不进入 Git，也不通过公开接口原样输出。

## 已确认的范围

- 迁移为可恢复、可重复执行的本地导入流程。
- 旧的 591 条资料和其数据库记录保留，但从默认检索、向量索引和首页统计中排除。
- 新资料须保留图书、章节和页码级的溯源元数据。
- 有文字层时直接提取；无文字层或提取结果不达标的页面才进入 OCR 队列。
- 只有新语料完成解析、校验和索引构建后，才切换默认语料版本。

不在本次范围内：将整本图书或解析全文提交到仓库、将旧资料物理删除、改变聊天/Agent 的业务编排逻辑、伪造或修改评测数据。

## 方案比较

### 推荐：版本化语料集 + 分阶段构建

新增 `heritage-books-v1` 语料集概念。导入过程生成带来源、页码和章节的片段；校验成功并完成索引后，事务性地将其设为 active，同时把旧语料集设为 archived。原有记录继续存在。

优点是可以回滚、重跑与精确追溯，且不会让解析失败污染当前检索。缺点是需要增加少量语料集状态与导入编排。

### 备选：将图书转 Markdown 后直接替换原 manifest

实现表面上较快，但无法区分旧新版本、失败时难恢复，而且超大文本难以在 Git 和审核流程中管理。因此不采用。

### 备选：每本书作为一个超大文档入库

无需章节切分，但召回粒度差、引用无法定位页码，对 RAG 答案质量影响明显。因此不采用。

## 架构与数据流

```text
本地图书目录
  -> 来源登记与 SHA-256 指纹
  -> PDF/EPUB 原生文字提取
  -> 低文字密度页的 OCR（可断点续跑）
  -> 章节识别与语义切块
  -> 校验报告
  -> heritage-books-v1（staged）
  -> BM25/向量索引构建与检索验收
  -> 原子切换 active corpus
  -> 原默认语料集变为 archived
```

### 来源登记

每本书记录稳定 `source_id`、文件绝对路径（仅本地配置）、相对展示名、格式、大小、SHA-256、导入时间和版权访问范围。导入前若指纹相同则跳过已完成步骤；指纹变化则建立新版本，不覆盖旧解析结果。

### 文本与片段

每个片段至少保存：`corpus_id`、`source_id`、书名、卷/章节标题、开始/结束页、文本、文本取得方式（native/OCR）、内容哈希和索引状态。切块以章节边界优先，再按现有检索器兼容的 token 长度与少量重叠切分。

OCR 的输入、页图和中间文本放在 Git 忽略的本地工作目录；已完成页以内容哈希标记，可在失败后继续运行。OCR 结果保留置信度/人工复核标记，低置信度片段不得自动发布。

### 激活状态

系统始终只有一个 `active` 语料集。旧的网页资料所属语料集切换为 `archived`；其原始表数据、文件和版本历史保持不变。默认检索、统计和图谱投影必须以 active 语料集为过滤条件；后台审查或回滚接口可显式读取 archived 语料。

## 失败处理与可恢复性

- 单个文件解析或 OCR 失败：记录失败原因、文件及页码，整个语料集保持 staged，绝不切换默认语料。
- 清单/哈希/元数据校验失败：阻止索引构建并生成可读报告。
- 索引构建或检索验收失败：保留 staged 数据供排障，旧 active 语料不变。
- 切换操作失败：在单个数据库事务内回滚状态，不产生双 active 语料集。

## 验收与测试

先编写并观察以下失败测试，再实现：

1. 同一图书指纹重复导入时不重复写入片段；指纹变化时创建新版本。
2. 原生文字提取为空的页面进入 OCR 队列；OCR 低置信度页阻止发布。
3. 每个已发布片段都能定位书名、章节与页码。
4. staged 语料在全部文件、片段和索引校验通过前不能成为 active。
5. 切换后默认检索只读取 `heritage-books-v1`；旧 591 条仍可由显式 archived 查询读到。
6. 任一切换失败都会恢复先前 active 状态。
7. 使用一组人工编写、可追溯到书中页码的查询集评测新索引；报告原始命中、缺失和评测脚本，不伪造指标。

## 实施顺序

1. 建立语料集/来源/片段状态模型与迁移，且不改变默认查询。
2. 实现可断点续跑的图书登记、文字提取和 OCR 队列，并用小型本地样本测试。
3. 实现章节切块、质量校验、索引构建和导入报告。
4. 让检索、统计和图谱投影按 active corpus 过滤。
5. 用真实图书构建 `heritage-books-v1`，完成抽样溯源与检索验收后执行切换。

## 操作与版权边界

部署者需在本机配置知识库根目录；命令不读取或上传网络数据。运行报告只输出书名、页数、片段数、失败页数和可追溯引用，不输出整段正文。仓库中只提交代码、空目录约定、元数据 schema 和不含版权正文的测试样本。
