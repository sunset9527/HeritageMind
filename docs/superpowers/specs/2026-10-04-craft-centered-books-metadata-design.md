# 以技艺为中心的本地图书元数据设计

## 背景

已激活的 `heritage-books-v1` 语料来自 10 本本地图书，共 7,688 个带书名、章节和页码的文本片段。它已经用于检索，但公开首页、百科、图谱和传承人页面仍主要依赖旧的 MySQL 发布内容。目标是在不删除旧数据、不把自动抽取结果伪装成事实的前提下，先将图书内容组织为可复查的技艺资料。

## 目标与边界

- 为当前激活语料建立以技艺为中心的候选元数据，而不是修改或删除旧 MySQL 内容。
- 每一项字段都能追溯到书名、页码、片段 ID 和原文摘录。
- 将明确陈述与仅被书中提及的内容区分开；缺失字段保持为空。
- 不调用在线服务，不要求 VPN，也不因模型猜测填充类别、传承人或地域。
- 本阶段只生成可供后续页面读取的结构化投影；公开页面切换将在该投影可验证后单独完成。

## 数据模型

在 `data/local_books_corpus/craft_metadata.json` 生成版本化、可重建的投影。顶层记录语料 ID、生成时间、来源书数量和条目数量；每个技艺候选包含：

```json
{
  "craft_id": "sha256 的稳定前缀",
  "project_name": "项目名称",
  "category": {"value": null, "status": "missing", "evidence": []},
  "regions": [],
  "inheritors": [],
  "description": {"text": "原文摘录汇总", "status": "mentioned", "evidence": []},
  "sources": [
    {"book_title": "书名", "chapter_title": "章节", "page": 1,
     "document_id": "book:...", "excerpt": "不超过固定长度的原文"}
  ],
  "status": "mentioned"
}
```

字段状态仅使用 `verified`（有明确模式和同页证据）、`mentioned`（书中出现但语义或上下文不完整）和 `missing`（未发现）。`verified` 的含义是“原书明确陈述”，并不等同于外部官方核验。

## 生成流程

1. 仅读取 `catalog.json` 标为 `active` 的语料；未激活、损坏或语料 ID 不一致时拒绝输出。
2. 流式读取 `documents.jsonl`，按片段中的项目标题、名录式条目和受控技艺词表发现候选项目。
3. 以“项目名称规范化 + 来源证据”合并候选；不得仅按人名或模糊关键词创建项目。
4. 对类别、地域、传承人使用保守的上下文模式抽取。候选传承人必须在同一证据片段中同时满足姓名和传承人身份提示；否则不写入 `inheritors`。
5. 将每个字段的原文证据写入资料库，原文摘要限制长度；保留完整文本所在的原始语料作为唯一全文来源。
6. 原子写入投影文件，并在文件中写入激活 `corpus_id`。下一次语料切换后，旧投影不得被误用。

## 公共展示的后续规则

后续首页统计读取图书数、片段数和文本字符数；百科、图谱、传承人页读取本投影而非旧库。页面默认展示 `verified`，可明确标记 `mentioned`；没有可用传承人证据时显示“当前图书语料未提取到带页码证据的传承人记录”，不回退到旧档案。

## 错误处理

- 缺少活动语料或元数据投影：API 返回明确的“语料尚未准备”状态，不回退旧数据。
- 抽取失败：保留已原子写入的上一版投影，并报告失败；不得产出半个 JSON 文件。
- 同名项目来源相互矛盾：保留为多个带证据的候选值，均标为 `mentioned`，不任意选一个作为事实。

## 验收与测试

- 单元测试使用小型 JSONL 语料验证：项目合并、页码证据、明确传承人、模糊姓名排除、缺失字段和语料 ID 校验。
- 先让新测试在生成器不存在时失败，再实现最小生成器使其通过。
- 使用真实 10 本书语料运行生成命令，报告候选项目数、带来源数、带传承人证据数和未能分类数；这些数字只作为运行结果记录，不预设目标值。
- 生成结果必须可由同一活动语料重复构建，且不修改 `documents.jsonl`、`catalog.json` 或旧 MySQL 数据。
