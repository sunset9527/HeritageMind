# HeritageMind v2.0 平台化设计

**日期：** 2026-09-12  
**状态：** 用户已确认设计，待审阅规格后进入实施计划

## 1. 目标与范围

HeritageMind v2.0 将当前可用的 Vue 3 + FastAPI 单体升级为可演示、可维护、可追溯的非遗 AI 知识平台。项目继续保持单体部署和清晰服务层，不提前拆分微服务。

本期包含：

- 统一的百科、传承人、来源证据、图谱候选和审计数据能力；
- 带审核闭环的知识图谱自动增量扩展；
- 复用业务服务的 MCP Server：本地知识库、Wikipedia、GitHub 可用，百度百科和通用 Web 搜索可配置但默认不启用；
- AI 搜索聚合接口与 Vue 搜索体验；
- 技艺百科、传承人档案、个人中心和扩展管理后台；
- Docker Compose、Nginx、HTTPS 生产模板与真实部署说明。

本期不购买服务器或域名、不申请或签发真实证书、不宣称系统已经上线。生产配置中的域名、邮箱、证书路径和公网地址使用明确占位符，并在文档中标记为“购买服务器与域名后替换”。

## 2. 架构原则

现有 FastAPI + Vue 3 应用保持为唯一部署单元。HTTP 路由、MCP 工具和后台任务复用同一服务层；不为“服务化”创建仅有名字的独立进程。

```text
Vue 3 前端
  ├─ Dashboard / AI 搜索 / 图谱 / 百科 / 传承人 / 个人中心 / 管理后台
  ↓
FastAPI
  ├─ API routers              ── HTTP / SSE
  ├─ MCP server               ── 标准工具接口
  ├─ services                 ── 搜索、图谱、百科、档案、审核、审计
  ├─ agents / retrieval       ── 已有 RAG、编排、图谱查询、多模态检索
  ↓
MySQL + Chroma + 本地图谱与媒体文件
```

## 3. 数据模型与审核闭环

新增或扩展的模型必须采用 Alembic 迁移，并使用现有 SQLAlchemy 2.0 风格：

- `craft_entries`：技艺百科元数据、slug、摘要、正文来源与发布状态；与现有 `data/crafts/*.txt` 对齐；
- `inheritor_profiles`：传承人姓名、关联技艺、地区、认定信息、简介、师承、代表作、发布状态；
- `source_evidence`：任意百科、档案或图谱事实对应的 URL、来源机构、抓取/录入时间和证据片段；
- `graph_change_candidates`：实体、关系、目标实体、证据、来源、抽取时间、状态及审核人；
- `audit_logs`：管理员的创建、编辑、审核、发布、配置变更等操作。

自动抽取永远只创建 `pending` 图谱候选，不直接写入正式图谱。管理员在后台审核批准后，系统才将候选合并到正式图谱数据并保留可追溯来源；拒绝和失败均保留原因。增量扫描仅处理新增或发生变更的已发布内容，并由可配置调度任务调用。开发环境不要求常驻调度器，生产 Compose 文档给出外部调度方式。

传承人首版内置 6 位重点示例。每个展示性事实必须链接至中国非遗网、文化主管部门或所属机构等可核验公开来源；缺少可靠来源的字段留空。首版不复制授权状态不明的图片，仅显示来源链接、版权说明或后续可替换的受授权媒体。

## 4. MCP 与 AI 搜索

MCP Server 暴露如下工具，并将每个工具的实际工作委托给可独立测试的服务：

- `search_local_knowledge`：查询项目内 RAG 知识库并返回文档证据；
- `search_wikipedia`：访问 Wikipedia 公开接口，返回标题、摘要与原始页面链接；
- `search_github`：访问 GitHub 公开接口，返回受限数量的仓库或代码搜索结果；
- `search_baidu_baike`、`search_web`：读取配置后调用适配器；未配置凭据或端点时返回结构化 `not_configured`，不会伪造搜索结果。

所有外部工具实施超时、响应大小限制、允许域名校验和明确错误分类。工具失败、不可达、限流或未配置只使该分支降级，并写入执行轨迹。

`POST /search/ai` 统一聚合已有 RAG、图谱、媒体和已启用 MCP 工具的结果，再沿用受引用约束的回答生成。响应包括回答、引用、关联图谱、媒体、各数据源状态以及安全的执行摘要。已有 `/query` 与 `/query/stream` 保持兼容。

## 5. 前端体验

- **Dashboard**：增强现有首页，补入最近访问、热门内容、图谱概览、推荐与真实可说明的统计；
- **AI 搜索**：Perplexity 风格单入口，显示回答、引用、相关图谱、图片、音频和工具降级状态；
- **知识图谱**：保留现有交互探索，增加候选更新后的可见关联、搜索、筛选、缩放和导出；
- **技艺百科**：23 项技艺的目录和详情，具备 SEO title、description、canonical 等元数据，并在构建阶段生成静态详情页；
- **传承人档案**：公开详情与来源引用，展示关联技艺、地区、师承/代表作（如有可靠来源）和图谱关系；
- **个人中心**：会话、收藏、偏好、个人资料及已有模型/API Key 配置的统一入口；
- **管理后台**：在现有质量、反馈与 Agent 配置上，加入用户、知识文档、图谱候选、传承人、Prompt、模型、媒体与审计入口。

页面不得用假指标、假搜索结果或未经核验的传承人事实填充。空状态和工具未配置状态必须向用户明确说明。

## 6. 权限与错误处理

- 百科、公开档案和已发布图谱内容可匿名读取；
- 个人中心的所有数据必须 JWT 鉴权且按用户归属过滤；
- 知识编辑、图谱审核、传承人发布、系统配置和审计查询均限管理员；
- 管理员只能调整注册表中已定义的 Agent 配置，禁止通过后台执行任意代码；
- 所有管理员写操作产生审计日志；
- 数据源、抽取和外部调用错误必须返回可读、可分类的错误状态，并不得打断本地问答能力。

## 7. 测试与验收

所有功能均按测试先行实施：先写最小离线、确定性 pytest 并确认其因为功能缺失而失败，再写最小实现使其通过。覆盖范围至少包括：

- 图谱候选去重、状态流转、审核合并和证据保留；
- 传承人/百科来源完整性与管理员权限；
- MCP 本地、Wikipedia、GitHub 工具契约，以及外部工具的未配置和故障降级；
- AI 搜索聚合响应、引用和执行摘要；
- 用户资源归属隔离与审计写入；
- 数据库迁移；
- Vue 类型检查与生产构建。

测试不依赖真实 LLM、线上 Wikipedia/GitHub、Redis、MySQL 或模型文件；外部访问以可注入客户端或确定性 stub 测试。上线前的真实集成测试另行记录，不得与离线测试混为一谈。

## 8. 交付顺序

1. 建立模型、迁移、审核、来源证据、审计和 MCP 工具底座；
2. 完成 AI 搜索聚合与图谱增量闭环；
3. 完成百科、传承人、个人中心与管理端各页面；
4. 添加 Compose、Nginx/HTTPS 模板、真实域名替换指南和全量回归。

每个阶段必须可运行和测试，最终在 v2.0 统一发布。未购买真实服务器和域名时，仅交付本地/容器可验证的生产就绪模板。
