# HeritageMind 全站场景编辑化重构设计

**日期：** 2026-10-03  
**状态：** 已获用户确认，待文档复核后实施

## 背景与问题

首页已采用深橄榄环境光、乡村场景照片、靛蓝线轴与越界织物的编辑式主视觉。其余路由仍是宣纸色背景上的通用卡片/表单，切换路由后像进入另一套产品。问题不是单纯色值不一致，而是缺少同一套图像叙事。

本次重构的目标是让公共路由共享“低照度自然场景 + 平面照片 + 越界材料 + 克制鎏金排版”的视觉语法，同时不改变已有 API、检索、会话、图谱和权限行为。

## 范围

### 覆盖路由

- 问答与搜索：`/chat`、`/search`
- 知识内容：`/encyclopedia`、`/encyclopedia/:slug`、`/inheritors`、`/inheritors/:slug`
- 探索与资料：`/graph`、`/media`
- 用户支持：`/profile`、`/settings`、`/login`、`/register`、404
- 共享外壳：`AppHeader`、`AppFooter`、全局令牌与表单状态
- 管理后台：`/admin` 仅同步颜色、字体、导航、控件令牌；不使用大幅场景插画，以保证运营效率。

首页保留为靛染场景的起点。撤销提交 `5ee749e` 中为解决错误问题所做的首页局部表面统一调整；但**不**恢复其中已去除的硬编码 `500+/100` 指标，首页继续读取真实服务端目录与文档摘要。

### 不在范围内

- 不更改后端 API、数据模型、路由、鉴权或 RAG 工作流。
- 不将装饰性生成图像描述为史料、非遗实拍或可核查来源。
- 不把管理后台重做成内容展示型页面。
- 不在本轮虚构或声称已扩充的知识库数据。

## 视觉系统

### 共享规则

公共页面的外层使用深橄榄环境底（接近首页 `#1c2016`），叠加低强度自然光和颗粒感。导航、栏目编号、文字比例和鎏金强调色贯穿所有页面。

每个页面由三层组成：

1. **环境层：** 深色、低照度场景及渐变，用于维持沉浸感。
2. **图像叙事层：** 一张裁切的场景照片，配合材料越出照片边界的装饰物。
3. **功能层：** 深色半透工作台或局部米白档案页。米白只作为可长读、引用、表单与结构化数据的局部介质，绝不再覆盖整页。

中文使用行楷作为展示文字，并以可用的楷体回退；英文和数字使用 Times New Roman。界面正文维持高对比、适度字距和键盘焦点，不能以装饰牺牲可读性。

### 页面场景映射

| 页面组 | 场景素材 | 内容构图 |
| --- | --- | --- |
| 问答、搜索 | 靛染线轴、织物、乡村/织造场景 | 线性侧栏和回答工作台；输入区作为底部工具条 |
| 百科、技艺详情 | 纸墨、刻版、书页/工坊场景 | 目录与条目为档案页，重点词与来源用鎏金细线 |
| 传承人、图谱 | 竹篾、经纬、工坊环境 | 档案卡/关系画布置于深色工作台，材料跨越页眉照片 |
| 多媒体 | 陶土或金工材料、工具环境 | 上传与媒体网格像整理中的资料台 |
| 个人、设置、登录注册、404 | 上述场景的安静裁切 | 表单或状态卡独立、克制，避免泛用 SaaS 外观 |

四组场景素材均为原创生成式编辑插画，只作界面装饰，配合明确的无史料含义的替代文本。它们不与知识库的可核查图片、证据来源混用。

## 架构

新增 `EditorialPageShell`，以明确的数据接口承接：

```ts
type EditorialScene = 'indigo' | 'ink' | 'bamboo' | 'clay'

interface EditorialPageShellProps {
  scene: EditorialScene
  index: string
  kicker: string
  title: string
  intro?: string
  readingSurface?: 'paper' | 'workbench'
}
```

- Shell 只渲染环境、标题区、装饰图层、响应式裁切和内容 slot。
- 各 View 继续拥有请求、加载、错误、空状态与交互逻辑；仅将页面主体放入 shell。
- 场景资产通过统一的 manifest 映射，而不在各视图重复硬编码 URL。
- `main.css` 重新定义全局背景、表面、文本、边框、表单和焦点令牌；管理后台只消费令牌。

## 响应式与可访问性

- 宽屏显示完整场景照片和越界材料。
- 小于平板宽度时，照片压缩为标题背景，越界材料缩小或隐藏；功能内容始终位于清晰的工作台/档案页上。
- 装饰图片使用空替代文本或明确的“编辑式艺术主视觉”描述，不与知识证据混淆。
- 文本、按钮、表单、列表与图谱控件维持可见 focus、语义标签和 AA 级对比。
- 动效遵循 `prefers-reduced-motion`。

## 验收与测试

1. 新增 Shell/场景 manifest 的单元测试：每个公共路由必须声明场景，且不引用非声明资产。
2. 保留并调整 Hero 的真实指标测试：服务端返回值显示为真实数据；请求失败显示 `—`。
3. 问答、图谱、登录和搜索既有 API 测试继续通过。
4. 为关键页面壳层添加挂载测试，验证标题、场景标识与内容 slot 存在。
5. 运行 `npm run test`、`npm run build`；记录已有 Rollup 体积提示但不伪称已解决。
6. 人工检查桌面与窄屏：切换路由后不出现整页浅米白底，且内容不会被装饰遮挡。
