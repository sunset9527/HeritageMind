# HeritageMind v1.6：可路由的 Agent 编排与执行轨迹

## 目标与边界

v1.6 使 HeritageMind 的 RAG、知识图谱与会话记忆成为真实、可观察且可降级的执行链，而非只在提示词中描述的能力。

- 保留 v1.4 已完成的 Query Rewrite、Planner、函数调用 Router 与三专家协作；不重复实现。
- Graph Agent 只查询仓库内 `data/heritage_graph.json`，不接 Web 搜索或其他外部数据源。
- Vue 3 是唯一的问答过程展示端；不重新引入 Streamlit。
- 会话记忆仅用于指代解析和检索改写，不能单独作为事实回答来源。
- 本版不修改数据库模式，也不新增 Alembic 迁移。

## 方案选择

采用“结构化路由 + 条件 Agent 流水线”。与直接把图查询塞进三专家链路相比，这个方案能清晰展示每次请求实际走了 RAG、图谱或混合路径；与按每个子问题创建并行 DAG 的方案相比，它避免在当前 23 份文档、约 65 个图谱节点的规模下增加不必要的延迟和复杂度。

## 工作流

```text
会话记忆（已有，仅提供上下文）
        ↓
Router：问题类型 + 执行路线 + 理由
        ↓
Planner（仅复杂问题）
        ↓
┌─ RAG / Hybrid → Research Agent → Query Rewrite + 混合检索 + 三专家
├─ Graph / Hybrid → Graph Agent → 本地 heritage_graph.json
└─ Memory → 仅影响指代解析与改写
        ↓
Answer Agent：融合可验证证据、生成回答、输出引用与轨迹
        ↓
缺口提示与 API 响应
```

### Router

在现有 `QuestionAnalysis` 基础上增加：

- `question_type`：`factual`、`comparative`、`procedural`、`open_ended`。
- `execution_route`：`rag`、`graph`、`hybrid`。
- `use_memory`：是否实际使用会话上下文。
- `route_reason`：可向用户展示的简短理由。

路由解析仍保持“三分支”可靠性：函数调用、content JSON、确定性关键词回退。三种解析均失败时，使用现有专家关键词规则并强制走 `rag`，不终止请求。

### Research Agent

Research Agent 是对现有 `dispatch_to_experts_node` 的职责命名与封装，不复制检索实现。它复用：Query Rewrite、BM25/向量/RRF、重排序、层级聚合与三专家分派。其产物为专家回答和精简的文档证据，而非把全文或提示词传给前端。

### Graph Agent

Graph Agent 基于 Router 给出的实体，在 `HeritageKnowledgeGraph` 中做精确和别名/子串匹配，并按关系扩展最多两跳。输出的证据由节点、关系、属性和“本地知识图谱”来源标识组成。

若未找到实体或图谱关系，记录 `fallback_reason` 并回退 RAG；不以 LLM 推测图谱中不存在的关系。RAG 也无有效证据时，交给现有知识缺口机制明确说明覆盖不足。

### Answer Agent

Answer Agent 复用当前回答融合和粒度适配能力，但输入改为结构化的 Research/Graph 证据。回答的引用只能来自成功的证据；失败、跳过或降级节点不会产生引用。Planner 仍仅约束复杂回答的组织结构，不新增检索。

## 状态与 API 契约

新增仅请求内存在的状态字段：

```text
route: { question_type, execution_route, use_memory, reason, fallback_reason? }
research_evidence: [...]
graph_evidence: [...]
workflow_trace: [...]
citations: [...]
```

`workflow_trace` 的每项包含节点名、`completed` / `skipped` / `fallback` 状态、耗时和简短说明。它不得包含提示词、API Key、会话原文或内部推理。

`POST /query` 保持请求体及原响应字段不变，新增：

- `metadata.route`
- `metadata.workflow_trace`
- 顶层 `citations`

`POST /query/stream` 的 `done` 事件返回同一组元数据。已有客户端忽略新增字段时仍可正常使用。会话历史不存储轨迹；打开已有或新历史消息时，没有轨迹便不展示该区域。

引用分为“知识库文档”和“本地知识图谱”两类，且明确其来源性质，不能伪装为外部权威资料。

## Vue 3 交互

在每条 AI 回答下方新增默认折叠的“本次执行”组件，而不改动现有右侧辩论面板：

```text
执行路线：Hybrid（文档检索 + 本地知识图谱）
[✓ 路由] → [✓ Planner] → [✓ Research] → [✓ Graph] → [✓ Answer]
```

展开后显示节点说明、耗时与完成/跳过/降级状态；Graph 节点显示“实体 —关系→ 实体”证据。引用继续放在回答下方，并按文档与图谱分组。轨迹属于单条回答，因而不会在多轮会话中串线。

## 错误处理

- Router 失败：关键词回退并执行 RAG。
- Planner 失败：跳过 Planner，继续执行选定路线。
- Graph 无命中或失败：轨迹标记 fallback，转向 RAG。
- Research 或单个专家失败：保留其他有效证据；无有效证据则触发缺口提示。
- Answer 失败：沿用现有安全降级，只返回已融合的有效内容。

## 验收与测试

所有新增后端测试使用 mock LLM、mock 检索器与固定本地图谱，不依赖 API Key、Redis、BGE、Whisper 或联网。

1. Router 覆盖四类问题、三条执行路线、函数调用/content JSON/关键词回退。
2. Graph Agent 覆盖实体匹配、一至两跳关系、无命中降级与图谱引用。
3. Answer Agent 覆盖只引用成功证据、无证据触发缺口、轨迹不泄露敏感或内部内容。
4. `/query` 与 `/query/stream` 最终元数据一致，旧字段保持兼容。
5. Vue 类型和执行轨迹组件覆盖 completed/skipped/fallback；执行前端构建校验。
6. 当前回归基线 `145 passed, 1 skipped` 不得下降，并增加 v1.6 的离线确定性测试。不得修改评测数据或编造指标。

## 非目标

- 不接入 Web 搜索、外部图数据库或图数据库迁移。
- 不实现每个 Planner 子问题的并行 DAG。
- 不重构 Streamlit 或新增 Streamlit 页面。
- 不改动 v1.5 会话表、历史表与用户偏好表。
