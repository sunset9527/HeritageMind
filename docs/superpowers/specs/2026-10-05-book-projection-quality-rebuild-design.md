# 活动图书百科与传承人重建

## 已复现的根因

- 公开百科、传承人和首页统计优先读取 `data/local_books_corpus/craft_metadata.json`，并非读取 MySQL 的 `CraftEntry` / `InheritorProfile`。
- 旧投影按关键词找项目，再把任何提及该词的片段前 280 字拼成简介；目录、索引、相邻项目及 OCR 错字因此进入公开正文。
- `申报地区或单位` 被误建为项目，其下挂有 20 位人物；旧规则跨 10 本书抽取人物，专门的传承人大典只贡献 2 条关系。公开人物的 `biography` 又直接复用了项目简介。
- 三批国家级主名录在书中分别标 518、510、191 项，但当前 1143 条投影混有扩展项目、误识别项与重复提及，不能拿差额当缺项数。

## 数据口径

主名录逐批核对 518 / 510 / 191 个序号。同名项目合并为一个百科条目，同时在审计结果中保留每批、每本书的原始出现次数、合并后覆盖数及缺失序号。扩展项目、山东省名录与通识读本单独统计，不充当三批主名录的缺项补丁。

传承人只允许从《国家级非物质文化遗产项目代表性传承人大典》提取。其他图书可以为项目提供资料，不得创建、确认或补全人物。人物必须同时具备该书页码、姓名、项目与独立的本人正文；识别不完整时进入待核清单，不公开推断关系。

## 重建流程

1. 保留原 PDF、`documents.jsonl` 和现有投影；从三批主名录序号及图典页建立独立的项目候选表，标出主名录或扩展名录。第一批已有的 518 条来源化名录记录作为交叉核对资料。
2. 从对应项目介绍页提取正文，排除目录、附录、申报/保护单位栏、相邻条目及索引。清理确定性的 OCR 换行与空格；存储原文证据和编辑后摘要，并保留页码。无法确认的错字不得猜改，应进入待核清单。
3. 从传承人大典的人物条目提取姓名、项目、人物正文及页码。优先按版面中的姓名和条目边界定位；跨页和多人物页必须明确分段。其他书出现的姓名不计入人物数。
4. 输出审计报告：各书原始条目数、去重覆盖数、主名录缺失序号、待核项目、待核人物、正文质量问题及来源页。
5. 新投影经数量校验、已复现错挂案例回归测试和原页抽样复核后再原子替换活动投影；后端重启后验证公开 API。

## 验收

- `申报地区或单位` 不再是项目；任天元不得挂在它下面，人物简介不得显示枣梆或山东附录的项目正文。
- 布洛陀等百科条目的简介来自自身介绍页，不以目录片段开头。
- 人物记录的来源书均为传承人大典；含人物的总数与该书可核对条目单独报告，不以全部 10 本书中的人名作分母。
- 三批主名录分别列出 518 / 510 / 191 个序号的核对状态；数量未核齐或 OCR 有疑义时报告差额，不伪造或补齐数据。
- 原始语料和旧 MySQL 数据不覆盖；切换前保留可回退的上一版投影。
