# HeritageMind v1.5：MySQL 会话记忆设计

## 目标与边界

在不迁移 MySQL、继续使用 Vue 3 前端的前提下，实现登录用户的跨轮对话记忆和自动偏好学习。用户可在昨天讨论昆曲后，今天在同一会话继续问“它有什么代表剧目？”，系统会从同一会话加载所需的近期上下文。

本版本不使用 `PostgresSaver`，也不实现全量 LangGraph 节点 checkpoint。当前工作流在单次 HTTP 请求内完整执行，无中断恢复需求；持久化“对话语义”比持久化每个节点的大型检索状态更适合该场景。

未登录用户保持无状态。现有 `chat_history` 保持一轮一条记录，不删除、不重写历史数据。

## 数据模型与迁移

新增 `chat_sessions`：

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| `id` | `CHAR(36)` 主键 | 服务端生成 UUID，会话公开标识 |
| `user_id` | FK `users.id`，级联删除，索引 | 会话归属 |
| `title` | `VARCHAR(120)` | 首轮问题截断生成的标题 |
| `created_at` / `last_active_at` | 非空，索引后者 | 排序与继续最近会话 |

在 `chat_history` 新增可空、带索引的 `session_id`，FK 指向 `chat_sessions.id`。旧记录保留 `NULL`，不会被错误归到新的会话。后续每轮记录均关联会话。

新增 `user_preferences`：`user_id`（主键且 FK）、`preferred_crafts`（JSON）、`preferred_profile`（`VARCHAR(20)`）、`profile_scores`（JSON）、`updated_at`。`preferred_crafts` 仅保存项目已知的标准技艺名，按频次与最近使用排序，最多五项。

## 服务层与 API

新增会话服务，单一职责如下：创建或校验会话、列出用户会话、加载会话上下文、更新活跃时间、保存一轮问答。所有以 `session_id` 查找的操作都必须同时约束 `user_id`，越权访问返回 404。

新增偏好服务，接收本轮显式技艺筛选、工作流识别出的标准技艺和用户主动选择的画像；累加/衰减评分，计算偏好。它不调用 LLM，避免从不可靠生成内容中学习偏好。

`POST /query` 的请求增加可选 `session_id`。已登录用户未传时创建会话并在响应 metadata 中返回 `session_id`；传入时恢复该会话。匿名请求忽略 `session_id` 并保持无状态。`/query/stream` 使用同一会话解析与写入逻辑，保证两种调用方式行为一致。

新增接口：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /chat/sessions` | 返回当前用户会话，按最近活跃时间倒序 |
| `POST /chat/sessions` | 创建空白新会话 |
| `GET /chat/sessions/{session_id}/messages` | 分页返回该会话已有轮次 |

`GET /chat/history` 维持兼容，不作为 v1.5 的会话加载主接口。

## 工作流记忆接线

`WorkflowState` 增加 `thread_id`、`conversation_context` 和 `memory_preferences`。在调用图前，服务层从 MySQL 读取当前会话最近四轮的问答；按时间正序格式化，并将总长度限制在 2,400 个字符。长度不足时保留完整轮次；超限时从最旧轮次开始淘汰，绝不截断当前用户问题。

上下文只传入问题分析、查询改写和回答生成提示词，帮助处理指代、省略和连续主题。它不替换 RAG 检索，不改变 `craft_name` / `craft_id` 的现有规则。当前请求的 `user_profile` 与 `craft_filter` 永远优先于记忆偏好；偏好只在未显式选择时提供默认值或提示。

图调用配置包含 `configurable.thread_id`，为未来替换为正式 MySQL checkpointer 保留稳定会话标识；v1.5 不依赖该配置恢复完整节点状态。

## 缓存、失败与隐私

带已登录会话的请求禁用热门问答缓存，避免不同会话因为相同问题得到脱离上下文的缓存回答。匿名无状态请求保留原缓存行为。

读取记忆、更新偏好或保存历史失败时，问答仍可完成；记录 warning，并在响应 metadata 标记相应降级。会话加载失败降级为空上下文，不向其他用户泄漏历史。所有会话、消息和偏好接口均需要 JWT 登录。

## Vue 3 交互

Pinia chat store 保存 `activeSessionId`，向 `/query` 传递它。进入 ChatView 时，登录用户加载最近会话；若存在会话，默认继续最近的一项并加载其轮次；否则展示“新对话”。侧边栏提供会话标题列表和“新对话”按钮，点击后替换消息列表与 `activeSessionId`。首轮完成后用响应 metadata 回填服务端创建的会话 ID。

现有学习深度、技艺与叙事开关保留。侧边栏可简洁显示系统已学习的技艺偏好，但不会暗中改变用户当前选择。

## 验收与测试

后端离线测试覆盖：会话创建与归属鉴权、匿名无状态、历史上下文按时间组装和长度上限、跨轮上下文进入工作流初始状态、标准技艺偏好归一化/上限/显式选择优先、会话请求绕过 QA 缓存、持久化异常降级。

前端测试或可重复的构建校验覆盖：激活会话 ID 随请求发送、加载会话替换 Pinia 消息、首轮回填自动创建的会话 ID、新会话清空消息。

最终执行完整 `python -m pytest tests/`，并执行 Vue 的 type-check/build。真实 MySQL 验证流程：登录 → 提问“介绍昆曲” → 新开或稍后继续同一会话提问“它的代表剧目有哪些” → 确认回答可承接昆曲主题，且另一账号不可读取该会话。
