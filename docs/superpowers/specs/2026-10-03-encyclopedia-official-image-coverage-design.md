# 百科官方图片覆盖设计

## 背景与问题

百科列表和首页技艺卡片目前固定拼接 `/crafts/{技艺名}.jpg`。该目录只包含早期 23 项本地图片，而后续由来源清单发布的百科条目没有对应文件，浏览器因此显示破图图标。问题同时影响百科列表和首页的技艺卡片。

用户要求为每个公开百科条目使用可追溯的官方机构或博物馆实拍图；页面不显示来源文字。不能用 AI 图片、通用图库或未核验网络图片冒充真实记录。

## 目标与非目标

### 目标

1. 每个 `/encyclopedia` 返回的公开条目都拥有一个明确图片状态：已核验官方外链、既有本地图片或待补充兜底。
2. 已核验图片记录真实图片 URL、来源页 URL、来源机构和核验日期；这些字段供审计和维护使用，不在公众卡片中显示。
3. 百科列表、首页技艺卡片和技艺详情页共用相同图片解析与失败处理行为。
4. 外部图片加载失败时，显示语义化的“待补充图像”视觉兜底，不出现浏览器破图标记、空白图片区或错误替代文本。
5. 不下载、不镜像、不二次分发外部图片；浏览器只请求已核验来源的图片 URL。

### 非目标

- 不把“名录记录”自动视作拥有可使用图片的授权。
- 不自动抓取或发布搜索结果、社交媒体、百科站或普通商业站的图片。
- 不在本期为图片建立向量检索、图片上传后台或版权授权工作流。
- 不在页面可视区域展示来源机构或原始 URL；平台仍保留内部来源记录。

## 数据模型与来源治理

新增版本化图片映射清单 `data/knowledge_sources/image_manifest.json`。每条记录包含：

- `craft_name`：与公开百科条目名称完全一致；
- `image_url`：允许浏览器加载的官方或博物馆图片直链；
- `source_page_url`：含图片和项目语境的来源页面；
- `source_name`：机构名称；
- `source_kind`：`official_heritage`、`government` 或 `museum`；
- `status`：`verified`、`legacy_local`、`pending_review` 或 `unavailable`；
- `accessed_at`：最后核验日期；
- `license_note`：仅说明外链展示边界，不将公开访问误记为再发布授权。

旧 23 项本地图片建立 `legacy_local` 记录或由映射解析器识别为本地资源。任何新条目只有在来源页、图片地址、机构身份与条目名称均通过核验后，才能标记为 `verified`。来源暂不可访问、图片地址不稳定或项目不匹配时标为 `pending_review`/`unavailable`，不发布为真实配图。

图片清单与知识资料清单保持独立：资料来源证明文字事实，图片来源证明视觉资产的出处，二者不能相互替代。

## 接口与前端行为

后端为公开百科 DTO 增加 `image` 字段：

```json
{
  "url": "/crafts/剪纸.jpg",
  "status": "legacy_local"
}
```

其中 `url` 可为旧本地 `/crafts/名称.jpg` 或核验后的官方外链。`source_page_url`、`source_name` 和 `license_note` 不返回到公开卡片接口；它们留在版本化清单供审核、修复和未来管理后台使用。

前端抽取一个共享的百科图片组件：

1. 加载前渲染固定比例的骨架；
2. `verified` 或 `legacy_local` 成功加载后显示实拍图；
3. 网络错误、`pending_review`、`unavailable` 或缺失 `url` 时切换为深绿、米白、鎏金的“待补充图像”视觉卡片；
4. 组件不渲染失效的 `<img>`，并提供包含技艺名的可访问文本；
5. 百科列表、首页 `CraftCarousel`、百科详情页复用此组件，避免分别拼接静态文件路径。

## 采集与发布流程

1. 以当前 `/encyclopedia` 的公开条目为基准生成缺图清单。
2. 对每项候选只从中国非遗网、文化和旅游部门、地方政府或公立博物馆站点寻找图源。
3. 人工式核验项目名、来源机构、图片所属页面和直链可访问性；将核验结果写入图片清单。
4. 先以小批量导入、接口测试和浏览器验证通过后，才扩展到下一批；不能为了显示数量把未核验候选设为 `verified`。
5. 当图片外链失效时，状态改为 `pending_review` 或 `unavailable`，前端自动兜底；修复地址后重新核验日期。

## 测试与验收

后端测试：

- 图片清单拒绝重复技艺名、非法状态、缺失来源页或 `verified` 项的非官方来源类型；
- 所有公开百科条目都能解析出图片状态；
- 既有 23 项解析为本地图片，不因新清单回归；
- 未匹配条目必须返回 `unavailable`，不能构造虚假的图片 URL。

前端测试：

- 传入已核验图片时渲染图片；
- 加载错误切换为兜底，不保留破损 `<img>`；
- 首页卡片和百科列表使用同一图片组件；
- `npm run build` 通过。

验收时在浏览器检查：已核验条目展示真实图片；未完成核验的条目展示一致兜底；页面不显示来源文字、不出现破图标；清单中可追溯每一个已展示外链的来源页和机构。

## 风险与取舍

外链方案避免了未获授权的下载和再分发，但依赖第三方站点稳定性、可能受到防盗链或图片迁移影响。因此使用明确兜底和状态管理，而不是承诺所有站点永不失效。图片来源不显示在卡片上是产品选择，不代表来源可省略；内部清单仍是公开平台的最低治理要求。
