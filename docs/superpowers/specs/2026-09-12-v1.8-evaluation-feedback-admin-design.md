# HeritageMind v1.8：回答评估、用户反馈与 Agent 管理闭环设计

**状态：** 已确认，待实施  
**范围：** v1.8 的独立质量闭环。它建立在已完成的动态协作与实时工作流主链之上，但不修改其协作策略。

## 1. 目标与边界

本期将每次已登录用户的问答闭合为“回答落库 → 自动过程质量评分 → 用户反馈 → 管理员分析与配置”。评分用于观察系统回答过程的健康程度、发现低质量链路与收集改进信号；它不是事实正确率，也不替代人工评审或 LLM-as-a-judge。

首版不调用额外模型进行评分，不引入 A/B 实验、任意 Python Agent 上传/执行、访客匿名反馈或对历史答案的重评分。未登录用户可以继续问答，但回答不落入可反馈的个人聊天记录，也不创建评价或反馈。

## 2. 方案选择

自动评分采用版本化、确定性的规则引擎。每一项分值、触发事实和规则版本都持久化，可在后台查看，避免出现无法解释或不可复现的“质量分”。评分维度只使用已生成的安全业务数据：

| 维度 | 观测信号 | 含义 |
| --- | --- | --- |
| 回答有效性 | 非空且达到最小有效长度 | 工作流是否产生可展示结果 |
| 证据支撑 | 引用数量与去重后的来源 | 是否提供可追溯参考，而非证据真伪判断 |
| 专家执行 | 成功进入最终来源的专家数量 | 专家协作是否实际参与 |
| 工作流韧性 | 节点 fallback/异常情况 | 链路是否发生安全降级 |
| 知识缺口处置 | `has_gaps` 与缺口说明 | 不因诚实承认未知而简单扣分 |

评分结果统一称为“过程质量信号”。当检测到知识缺口但答案明确说明边界时，相关维度给予合理得分；禁止把“不确定”误判为低质量。

## 3. 数据模型

新增三类实体，均关联已有 `chat_history.id`：

1. `answer_evaluations`
   - 一条聊天回答一条自动评价（`chat_id` 唯一）；
   - 保存 `total_score`、`rule_version`、结构化 `score_details`、创建时间；
   - `score_details` 包含每个维度的分数、上限、机器可读原因码和面向管理员的说明。
2. `user_feedback`
   - `user_id + chat_id` 唯一，`sentiment` 仅为 `up` 或 `down`，`comment` 可空；
   - 再次提交同一回答时更新原记录及 `updated_at`，而不是重复计数；
   - 用户只能读写自己的反馈。
3. `agent_configurations`
   - 一条已注册 Agent 一个可选覆盖配置，`agent_id` 唯一；
   - 包含 `enabled`、展示名称、能力描述、协作优先级、受限 JSON 参数、更新时间与最近修改管理员；
   - 数据库配置不是 Agent 可执行代码。删除覆盖记录代表恢复注册表默认值；不可通过后台创建未知或可执行的 Agent。

数据库迁移会对 `chat_id`、`user_id`、筛选字段与唯一约束建立必要索引。所有时间以 UTC 保存。

## 4. 回答与评价写入流程

```text
已登录 /query 或 /query/stream 完成
  → 保存 ChatHistory 并取得 chat_id
  → 使用最终响应元数据计算规则评分
  → 写入 AnswerEvaluation
  → 非流式 response.metadata / SSE done 返回 chat_id 与 evaluation 摘要
  → 前端回答卡片显示反馈入口
```

回答保存失败时不伪造 `chat_id`、评价或可提交反馈的 UI。评价写入异常不得中断已生成的回答：记录服务端错误，响应不带评价摘要。流式完成事件只在聊天记录与评价均获得真实 ID 后附带它们。

为让历史会话也可渲染反馈入口，聊天详情响应会带回该回答当前用户的反馈和评价摘要；历史记录不存在评价时按兼容数据处理，不将其显示为零分。

## 5. API 与权限

新增所有写操作均由后端执行权限校验，前端路由守卫仅改善体验：

| 接口组 | 访问者 | 用途 |
| --- | --- | --- |
| `POST /feedback`、`GET /feedback/chat/{chat_id}` | 已登录且聊天归属本人 | 新建或更新本人反馈、读取本人反馈 |
| `GET /admin/evaluations`、`GET /admin/feedback` | `role=admin` | 分页、筛选、查看关联问题、回答与链路摘要 |
| `GET /admin/agents`、`PATCH /admin/agents/{agent_id}`、`DELETE /admin/agents/{agent_id}/override` | `role=admin` | 查看、修改与恢复已注册专家的配置 |

反馈 `sentiment`、评论长度、分页上限、排序字段、Agent ID、参数键和值均在服务端白名单校验。管理员查询返回的问题、答案、评价和反馈均不包含密码哈希、令牌、API Key、系统提示词或完整检索上下文。

## 6. Agent 配置的运行时语义

每个新请求在构建 Dispatcher/工作流前，将已注册的三个专家与启用的配置覆盖合并：

- 被禁用的专家不进入 Router 可选集合、不实例化、不出现在实时 DAG；
- 展示名称和能力说明会反映到 Router schema、来源 Agent 与后台；
- 协作优先级只用于确定性地整理已验证参与者的协作计划，不覆盖 Router 的专业匹配结论；
- 参数仅支持预定义的安全键（例如最大协作消息数或单 Agent 可见开关），未知键被拒绝；
- 配置修改仅影响之后开始的新请求，已保存的回答、评价和轨迹不被改写。

若配置读取异常、全部专家被禁用或配置非法，则回退到默认注册表，并记录可诊断日志；请求不能因管理配置而失去所有回答能力。

## 7. 前端交互

### 7.1 回答反馈

在已持久化且当前用户登录的 assistant 回答下显示“有帮助 / 无帮助”两个按钮。首次点击立即提交；再次选择另一方向更新原反馈；点击当前已选方向可取消。选择“无帮助”后展开可选文字意见。未登录或还在流式生成、没有 `chat_id` 的回答不显示可写反馈入口。

### 7.2 管理后台

新增 `/admin`，导航仅对管理员显示，路由增加 `requiresAdmin`。页面含三个轻量标签页：

1. **质量评估**：按日期、分数区间、是否有缺口、专家筛选；查看分数明细和关联问答。
2. **用户反馈**：按日期、点赞/点踩、是否有文字意见筛选；查看关联问答与评价摘要。
3. **专家配置**：列出三位注册专家，编辑启停、显示名称、能力说明、优先级与允许参数；提交后给出“仅影响后续请求”的提示。

不引入图表库或管理框架。页面使用现有 Vue、Tailwind/CSS、认证 store 和请求封装，移动端保持可读的表格降级布局。

## 8. 兼容性、测试与验收

- 既有 `/query`、`/query/stream`、聊天历史接口字段不移除；新增 `chat_id`、评价摘要和用户反馈字段均为可选扩展。
- `admin` 的前端隐藏不作为安全边界；每个后端接口都测试普通用户、匿名用户和管理员的行为。
- 所有新评分逻辑先以确定性单元测试表达，再实现最小代码。测试不调用外部 LLM、向量库或真实数据库服务。

验收包括：

1. 成功的登录问答返回真实 `chat_id` 和可解释评分摘要；知识缺口回答不会因诚实披露被简单归零；
2. 同一用户对同一回答点赞、改为点踩、取消反馈均只保留一条记录；越权聊天不可反馈；
3. 非管理员访问任一 `/admin` 接口得到 403，管理员可按条件筛选记录；
4. 禁用一位专家后，新请求的 Router 和动态 DAG 不再提供该 Agent；删除覆盖后恢复默认；
5. 后端测试、`vue-tsc --noEmit` 和前端生产构建实际通过；只报告真实运行结果。
