# HeritageMind v1.8 实施计划：评估、反馈与 Agent 管理闭环

> 前置规格：[v1.8 回答评估、用户反馈与 Agent 管理闭环设计](2026-09-12-v1.8-evaluation-feedback-admin-design.md)

## 实施原则

- 所有生产行为严格测试先行：先写并观察目标测试因缺少功能而失败，再写最小实现使其通过。
- 不将规则评分称作正确率，不调用额外 LLM，不伪造质量、延迟或用户反馈数据。
- 新增字段保持向后兼容；未登录问答与既有聊天历史保持可用。
- 管理端配置是受白名单限制的数据覆盖，绝不允许数据库值创建或执行任意 Agent 代码。

## 1. 规则评分领域模型与持久化

**文件**：新增 `src/services/evaluation.py`、`src/models/evaluation.py`、`src/models/feedback.py`、`src/models/agent_configuration.py`；更新 `src/models/__init__.py`；新增 `migrations/versions/004_add_v18_quality_feedback_admin.py`；新增 `tests/test_v18_evaluation.py`。

1. 先写纯函数测试：同一输入始终得到相同总分、规则版本和明细；无回答、无引用、fallback、知识缺口但有披露等边界均有清晰原因码。
2. 实现不依赖数据库的 `evaluate_response()`，输入为最终回答、引用、来源 Agent、缺口信息和工作流摘要，输出受限的 `EvaluationResult`。
3. 定义 `AnswerEvaluation`、`UserFeedback` 和 `AgentConfiguration` 模型，设置外键、唯一约束、UTC 时间、索引与 JSON 字段。
4. 建立迁移及轻量服务函数：创建/读取评价，按聊天归属 upsert/cancel 反馈，读取或重置 Agent 覆盖。

**验收**：评分规则及数据库约束均由离线 pytest 覆盖；评分明细可解释且没有任何外部模型调用。

## 2. 已登录问答的记录 ID 与评价写入

**文件**：更新 `api.py`、`src/services/chat.py`、相关 schemas；新增 `tests/test_v18_query_evaluation_contract.py`。

1. 先写 API/服务测试：成功保存的问答返回真实 `chat_id` 与评价摘要；未登录回答没有可写反馈 ID；评价写入失败不影响回答返回且不伪造成功。
2. 让既有 `save_chat_history()` 的返回实体成为单一 `chat_id` 来源；非流式和 SSE 完成路径均在 commit/refresh 后生成评价。
3. 在 `/query` 的 metadata 和 `/query/stream` 的 `done` payload 中添加可选的 `chat_id`、`evaluation` 与 `feedback` 摘要；旧字段保持不变。
4. 扩展聊天详情/会话消息的 schema，使前端加载历史消息时能取得评价和当前用户反馈；缺失历史数据以 `null` 表示。

**验收**：普通问答、流式问答、历史加载、保存失败和匿名问答的契约测试全部通过。

## 3. 用户反馈 API 与所有权校验

**文件**：更新 `api.py`，新增或更新 `src/schemas/feedback.py`、`src/services/feedback.py`；新增 `tests/test_v18_feedback_api.py`。

1. 先写测试：登录用户可创建、替换与取消自己对一条聊天回答的反馈；同一 `(user_id, chat_id)` 不能产生多行；他人聊天与匿名请求分别被拒绝。
2. 实现 `POST /feedback` 的幂等 upsert/cancel 语义和 `GET /feedback/chat/{chat_id}` 的本人读取。
3. 对 sentiment、comment 长度及 chat ownership 做后端校验；不根据前端传入的用户 ID 决定归属。
4. 在问答与历史响应中只返回当前用户自己的反馈，不向其他普通用户泄露反馈内容。

**验收**：授权、越权、更新、取消和评论校验均有真实服务/API 测试。

## 4. 管理员 API 与受限 Agent 配置

**文件**：更新 `src/deps.py`、`api.py`、`src/agents/registry.py`、Dispatcher/工作流构建入口；新增 `src/schemas/admin.py`、`src/services/admin.py`；新增 `tests/test_v18_admin_api.py`、`tests/test_v18_agent_configuration.py`。

1. 先写权限测试：匿名为 401、普通用户为 403、管理员能读写；路由与前端隐藏不作为验证条件。
2. 添加明确的 `require_admin` 依赖；实现管理员评价/反馈分页筛选，所有排序键、筛选值和页大小白名单化。
3. 实现注册 Agent 默认定义与数据库覆盖的合并函数。先测试禁用 Agent 后无法由 Router 选中、优先级仅影响协作排序、删除覆盖恢复默认、未知 `agent_id`/参数被拒绝。
4. 实现管理员的 Agent 列表、更新和“删除覆盖/恢复默认”接口。只允许三个注册 ID 与预定义安全参数；不提供运行时代码上传或未知 Agent 创建。
5. 在每次新工作流构造时加载有效配置；读取失败或所有 Agent 被禁用时使用默认注册表并记录日志。

**验收**：管理员数据不会泄露密钥或提示词；配置即时影响下一次请求、历史答案不变；后端安全降级可测试。

## 5. Vue 反馈控件、后台与权限体验

**文件**：新增 `frontend/src/components/chat/AnswerFeedback.vue`、`frontend/src/views/AdminView.vue`、必要的 admin 子组件与 API 模块；更新 `frontend/src/types/index.ts`、`frontend/src/api/query.ts`、`frontend/src/api/chat.ts`、`frontend/src/stores/chat.ts`、认证 store、`frontend/src/router/index.ts`、`frontend/src/views/ChatView.vue`、导航组件。

1. 先为反馈状态归约/请求参数写最小 TypeScript 测试或可执行断言：乐观状态只在 API 成功后确认、切换/取消反馈正确、无 `chat_id` 或未登录时禁用。
2. 将可选 `chatId`、`evaluation`、`feedback` 加入消息元数据，并在流式 `done` 和历史加载时填充。
3. 实现回答下方的反馈控件：点赞、点踩、可选文字、编辑/取消、登录与未持久化状态提示；提交错误应回滚可见状态并提示用户。
4. 新增 `/admin` 与 `requiresAdmin` 守卫；导航只对 admin 展示入口，但 API 拒绝仍是最终安全边界。
5. 实现管理员三标签页与分页筛选：评估明细、反馈记录、三位专家的受限配置编辑和“只影响后续请求”提醒。

**验收**：历史和实时回答都正确渲染；普通用户不能进入后台页面；`npx vue-tsc --noEmit` 与生产构建通过。

## 6. 回归与人工验收

1. 运行新增测试并完整执行 `python -m pytest tests/ --basetemp <可写临时目录>`。
2. 执行前端类型检查与生产构建，记录真实警告和结果。
3. 在已配置有效模型、MySQL 与本地 BGE 的环境中人工验证：登录问答得到评分和可写反馈；修改/取消反馈；管理员筛选记录、禁用专家并发起新的问答、恢复默认。
4. 提交前检查 `git status --short`，只纳入本期设计、迁移、服务、接口、前端和测试文件；不触碰既有评测数据或 README。
