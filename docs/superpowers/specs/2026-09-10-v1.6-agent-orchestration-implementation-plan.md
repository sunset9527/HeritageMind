# HeritageMind v1.6 实施计划

> 前置规格：[v1.6 Agent 编排与执行轨迹设计](2026-09-10-v1.6-agent-orchestration-design.md)

## 实施原则

- 先写失败的离线确定性测试，再写最小实现使其通过。
- 不修改现有评测集、v1.5 数据库迁移或未合并的 `README.md`。
- 所有新增测试都不依赖 API Key、网络、BGE、Redis、Whisper 或持久 Chroma。
- 原有 `/query` 字段与客户端行为保持可用；新增轨迹字段允许旧客户端忽略。

## 1. 路由、证据与轨迹契约

**文件**：`src/agents/dispatcher.py`、`src/workflow/state.py`、新增 `tests/test_v16_router.py`

1. 先固定 Router 的 function-call、content JSON、关键词回退三分支测试，覆盖四种问题类型、三条执行路线和 `use_memory`。
2. 扩展 `QuestionAnalysis` 与 `route_question` schema：`question_type`、`execution_route`、`use_memory`、简短路由理由；所有枚举做白名单清洗。
3. 新增 Router 字段无法解析时保留既有专家选择规则，并采用 `open_ended / rag / False` 的安全默认值。
4. 在 `WorkflowState` 添加 `route`、`research_evidence`、`graph_evidence`、`workflow_trace`、`citations`，并在 `create_initial_state` 初始化。
5. 提供内部 trace helper，只记录节点名、状态、耗时和用户可读说明，绝不记录提示词、会话原文或密钥。

**验收**：mock LLM 下 Router 全部通过；已有 dispatcher/router 测试继续通过。

## 2. 本地图谱 Agent

**文件**：新增 `src/agents/graph_agent.py`、`src/agents/__init__.py`、新增 `tests/test_v16_graph_agent.py`

1. 先写精确实体命中、子串/别名匹配、关系输出、一至两跳上限、无命中和图谱加载失败测试。
2. 实现可注入 `HeritageKnowledgeGraph` 的 `GraphAgent`；生产路径只读加载 `settings.heritage_graph_path`，测试不依赖 `api.py` 全局状态。
3. 输出统一的节点、边、深度、`local_knowledge_graph` 来源和可读引用标题。
4. 不存在实体、无关系或查询异常均返回空证据及失败原因；不调用 LLM 猜测关系，也不写回 `heritage_graph.json`。

**验收**：Graph Agent 完全离线可测，且没有写操作。

## 3. 条件工作流与降级链

**文件**：`src/workflow/nodes.py`、`src/workflow/graph.py`、新增 `tests/test_v16_workflow_routes.py`

1. 先为 `rag`、`graph`、`hybrid` 写节点选择和 trace 顺序测试。
2. 将现有 `dispatch_to_experts_node` 封装为 Research 职责，复用 Query Rewrite、共享 `MultiSourceRetriever`、层级聚合和三专家；从专家结果中提炼最小文档证据。
3. 新增 Graph 节点，只在 `graph`/`hybrid` 执行；无证据时记录 fallback trace 后执行 Research。
4. 保留现有 Planner 触发条件；会话记忆仅参与现有路由与改写，不能绕过检索/图谱事实证据。
5. Answer 路径只将成功 RAG/Graph 证据转为 citations；无有效证据时复用 gap detector。
6. 在 `HeritageWorkflowGraph` 注册节点、条件边和可读标签；为既有 SSE/测试保留兼容节点映射。

**验收**：三条路线、图谱无命中回退、单专家失败、无证据缺口均有确定性测试；v1.4 Planner/Rewrite/Dispatcher 与 v1.5 Memory 不回归。

## 4. API 与 SSE 契约

**文件**：`src/workflow/state.py`、`api.py`、新增或扩展 `tests/test_v16_api_contract.py`

1. 用 mock workflow 为 `/query` 与 `/query/stream` 写契约测试，断言旧字段仍在，且最终 `route`、`workflow_trace`、`citations` 一致。
2. 在响应模型声明顶层 citations，将 route 与 trace 放入 metadata。
3. 更新 SSE 节点标签与 done 事件；中间事件不得泄漏敏感状态。
4. 保持 chat history 结构不变，不为轨迹增加数据库迁移。

**验收**：两种 API 终态可比较，旧必填字段零丢失。

## 5. Vue 执行轨迹

**文件**：新增 `frontend/src/components/chat/WorkflowTrace.vue`、`frontend/src/types/index.ts`、`frontend/src/stores/chat.ts`、`frontend/src/views/ChatView.vue`

1. 先定义 route、trace、citation TypeScript 类型，并让缺失新字段安全降级。
2. 实现默认折叠的 `WorkflowTrace`：摘要显示路线和节点串；展开显示 completed/skipped/fallback、耗时、说明及图谱关系证据。
3. `sendQuestion` 将 response metadata 映射到单条 assistant message；历史消息无 trace 时不渲染。
4. 将组件放在回答下方、引用上方；不修改右侧辩论面板，不引入 Streamlit。
5. 执行前端类型/构建校验，修复严格类型错误。

**验收**：三种状态可区分；窄屏不挤压正文；旧历史消息正常。

## 6. 回归与真实验收记录

1. 先跑 v1.6 离线测试，再跑 `python -m pytest tests/`。
2. 执行前端构建校验。
3. 在用户已配置本地 MySQL、BGE 和有效 LLM Key 时，手验图谱事实问答、复杂 Hybrid 对比、同会话指代追问；只记录实际结果，不编造性能或质量数字。
4. 报告真实通过数、跳过数与未满足的环境依赖。
