# HeritageMind README 重写设计

## 目标

用一份中文 README 同时服务两类读者：

1. GitHub 访客、面试官或招聘者，能在短时间判断项目的问题意识、工程边界与可验证质量。
2. 实际使用者，能在 Windows PowerShell 上完成本地启动、配置 API Key 并访问接口。

README 不再承担完整 API 手册职责；详细端点以 Swagger `/docs` 为准。

## 信息架构

1. **Hero**：项目定位、简洁技术标签、真实能力摘要。
2. **为什么做**：非遗知识的覆盖边界，以及系统以知识缺口检测避免“假装全知”的产品取舍。
3. **核心能力**：混合检索、三专家、会话记忆、本地图谱，以及 v1.6 的结构化路线/证据/轨迹；已完成与后续明确分开。
4. **当前架构**：Vue 3 → FastAPI → LangGraph → RAG / Graph / Memory → MySQL、ChromaDB 与本地图谱。
5. **快速开始**：PowerShell 为主；API 默认 `8001`、Vue 默认 `5173`；环境变量、数据库迁移、启动与 Swagger 入口。
6. **可复现验证**：检索评测、测试命令及指标适用范围。
7. **工程导航**：目录、文档、路线图、贡献与精简版本记录。

## 可信度规则

- 所有指标标注来源与条件。
- 检索结果表述为：94 条有效自建题、Hit@5=100%，语料为 23 篇且主题区分度较高，不能外推为通用检索能力。
- 测试表述为：`154 passed, 1 skipped`，并给出使用可写临时目录的运行命令。
- 图谱表述为：65 节点、39 条关系，数据来自仓库内 `data/heritage_graph.json`。
- v1.6 只声明已经完成的结构化 Router、本地只读 Graph Agent、可追溯响应与 Vue 执行面板；不将 Web 搜索、并行 DAG 或多模态理解写成已完成。
- 不使用虚构徽章、未验证性能数据或“媲美某产品”式对标。

## 文档边界

- 仅引用仓库已提交的演示资源；不引用本地临时截图、构建产物或日志。
- 快速开始只说明 HeritageMind 自身端口与配置，不提及其他本地项目或端口占用背景。
- 移除过时的 Streamlit 主路径、旧 API 数量、旧端口、重复版本线和冗长端点清单。
