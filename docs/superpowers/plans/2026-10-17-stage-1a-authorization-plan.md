# HeritageMind 阶段 1A：权限矩阵与资源归属实施计划

> 对应设计：`../specs/2026-10-17-stage-1a-authorization-design.md`

## 1. 固化敏感路由权限契约

1. 新建 `tests/test_stage1a_authorization.py`，从 FastAPI 路由依赖树读取真实依赖，而不是只搜索源码文本。
2. 枚举 Prompt、媒体写入、知识文档上传、手动转写和三类索引重建端点，断言全部绑定 `require_admin`。
3. 断言新增 `/admin/media` 绑定管理员依赖，公开媒体列表保持匿名可读。
4. 先运行测试，确认缺少依赖和管理端点不存在导致预期失败。
5. 为现有端点增加最小 `Depends(require_admin)`，新增管理媒体列表，使契约转绿。

## 2. 建立媒体公开投影

1. 在 `tests/test_media_authorization.py` 先写 Service 测试：数据库同时存在 draft、reviewed、published 时，公开列表、总数、详情和存储名查询只能看到 published。
2. 在 `src/services/media.py` 增加公开查询函数，确保结果与 count 使用相同发布状态谓词。
3. 修改公开列表、详情和文件接口使用公开查询；管理员列表继续使用全量查询。
4. 写 API 行为测试，验证草稿列表不可见、详情和文件返回 404、发布后可访问。
5. 修改图片文字搜索、相似图片搜索和音频搜索，最终结果必须回查数据库发布状态；先写失败测试再实现。
6. 将转写状态接口和手动转写接口改为管理员专用。

## 3. 补齐用户资源归属

1. 为收藏创建写失败测试：当前用户不能用其他用户的 `chat_id` 创建收藏，响应为 404且数据库无新增记录。
2. 增加自己的聊天记录可正常收藏测试。
3. 在收藏路由中复用 `get_chat_detail(db, chat_id, current_user.id)` 验证归属。
4. 补充或复跑会话详情、会话消息、聊天详情和反馈的跨用户访问测试，确保既有边界未回归。

## 4. 对齐前端媒体权限体验

1. 扩展 `frontend/src/api/media.ts`：公开列表调用 `/media/list`，管理员列表调用 `/admin/media`，增加状态修改 API。
2. 为 `MediaView.vue` 先写 Vitest 失败测试：普通用户不显示上传/删除/审核操作，管理员显示管理操作。
3. 媒体页从认证 Store 读取当前用户；管理员加载管理列表，其他用户加载公开列表。
4. 修复筛选参数：第一个参数传 `selectedCraft`，第二个参数传 `filterType`。
5. 增加状态选择的最小管理操作，不在本阶段建设完整审核工作台。

## 5. 回归、记录与提交

1. 运行阶段 1A 新增测试和受影响的鉴权、媒体、会话、反馈测试。
2. 运行后端全量离线测试。
3. 运行前端 Vitest、TypeScript 检查和生产构建。
4. 运行 Ruff、`git diff --check`、Compose 静态解析和定向敏感信息扫描。
5. 新建版本化工程测试记录，写明功能提交、真实通过数、警告和阶段 1B/1C/1D 未完成项。
6. 分别提交实施计划、功能代码和验证文档，确保 Git 工作区干净。

## 交付顺序

严格按“路由权限 RED/GREEN → 媒体公开投影 RED/GREEN → 归属 RED/GREEN → 前端 RED/GREEN → 全量回归”推进。任何失败测试只通过修改生产行为解决，不修改预期绕过安全要求。
